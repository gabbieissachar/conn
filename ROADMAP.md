# Conn roadmap

What Conn has shipped, what comes next, what is already decided, and what still needs the owner. Last updated 2026-11-08, on the Conn fix queue branch, after Campus transcripts on the reader's own page (and New conversation in Campus, the Campus 403 sign-in fix; the fix queue itself: wrong transcript, asks read state, sidebar, permission prompts).

Update rule: every Conn change updates this file in the same branch (see "How to keep this current" at the end).

## Short answer

Conn is a working replacement for the Herdr part of the old setup, and also shows ShopBack Campus conversations (read and, behind a switch, write; first live check is N13). It draws the live sidebar and panes of a Herdr session, shows the reader and organizer as web views, edits text files, and has one guarded write (the compose box). It is **observe-only**: it cannot resize a pane, and the compose box has only been tried against the stand-in Herdr. 363 unit tests (three lab-only ones skip unless a lab session is named) pass, and a full fixture `--ui-check` passes in both flag states on the fix-queue branch (211 checks with the Agent view off, 216 with `--agent-view`, none failing); the live run of the Watch steps was read-only against the real reader. Memory fits the budget (about 1.0 to 1.1 GB for the whole setup against 4.1 GB before). The CPU target passes on Conn's added share (D6). Several things were checked in process only and need a person at a real screen.

**Next three steps, in recommended order:**

1. **Try `main` on a real screen** (N1). A person runs the short hand-check list below. It settles the items that no scripted check can see (trackpad scroll, keys typed at the window, text size on the Retina display, pane first draw).
2. **One small fix that needs nothing from Herdr** (N2). Stop showing a superseded reader load as "not reachable". Wide panes wait for control mode (W1).
3. **Set up a Herdr lab session, then build control mode** (N4, N5). The lab step is unblocked: a running `default` session now exists beside `esim`. Window-sized panes need a pane resize, which is a write. A lab session is the safe place to test it, and it also settles compose-box questions that are open on real Herdr (N6).

Measured against the decision D5 target (under 1.2 GB and 6% idle CPU, baseline 4,093 MB and 15.5%):

- Memory: whole setup 1,033 to 1,120 MB in quiet windows with both servers and the reader page open. It passes with little room.
- CPU: Conn adds about 3 points (0.8 to 1.25% in the app, 2 to 2.4 in the Herdr server). The whole setup was 3.2 to 4.4% in quiet windows, but 7 to 23% on busy windows because of the reader's Python worker, which Conn does not control. See D6.
- Watch (6 Nov, real fleet: 39 agents, the reader server and worker running, Conn started read-only in test mode): 3 columns, 3 lite pages of 43, 41 and 223 MB (web content 307 MB); 4 columns, 43, 257, 258 and 397 MB (955 MB; a later run with other sessions: 836 MB). A page costs what its conversation costs: about 40 MB for an ordinary one, 220 to 400 MB for the largest. For comparison one full reader page measured 297 to 311 MB in the same hour. Conn-side total (app 51 to 74 MB, web content, the shared GPU and Networking processes about 75 to 120 MB): full reader 480 MB, Watch with 3 columns 435 MB, with 4 columns about 1.1 GB. With the reader server (667 to 748 MB), its worker (210 to 232 MB), the organizer server (24 MB) and Herdr (85 MB) the whole setup is about 1.5 GB with the full reader, 1.4 GB with 3 columns and 2.1 GB with 4 columns, against the 1.2 GB D5 target. The target was already missed at baseline: the reader server alone is now over half of it. 3 columns cost about what the full reader costs; 4 columns break the target badly whenever the largest conversations are among them.
- Each visible working pane costs the Herdr server 3 to 9 points. Panes stream only while visible and stop after 30 s in the background.

## How to keep this current

- Each Conn change updates this file in the same branch. A change that ships a piece adds a row to Done with its commit ids and removes or edits the Next or Later row it closes. A change that finds new work adds a row with its source.
- Commit ids go in once the commit exists: add them in a follow-up commit on the same branch, or amend before the branch is merged.
- When the owner answers a keyed question, move it to "Decided and deferred" with the answer and its reason, and delete the card.
- Keep "Short answer" true: re-check the next three steps and the test counts at every update.
- Keep it self-contained: cite decision ids, commit ids and report sections, never paths outside this repository.
- Plain language, short sentences, no em dash.
