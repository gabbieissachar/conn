# Conn

Native Mac workspace app: Herdr panes, the transcript reader, the organizer and a plain editor with a folder browser in one window. Decisions: see the native app decision ledger kept by the leader-workspaceos firstmate home.

**What is done and what is next: [ROADMAP.md](ROADMAP.md).** Every change to Conn updates it in the same branch.

Conn is a client of `herdr server`: Herdr stays the backend and keeps every agent alive when the app quits. The app draws a native sidebar from Herdr's snapshot and events, streams visible panes into a terminal pane, shows the reader and the organizer as web views, edits text and markdown files, and runs Herdr's own client in a terminal pane (Herdr client mode, below).

**What draws the panes.** Decision B2: SwiftTerm is the terminal engine, behind a protocol (`TerminalEngine`). It is the default pane view. A second engine, a 450-line cell grid ported from the prototype, stays selectable with `./run.sh --renderer grid`; it is the one whose output the agents that built this could see in screenshots, so it is the reference when a SwiftTerm pane looks wrong. SwiftTerm also runs the Herdr client pane.

SwiftTerm normally draws from a display-link tick that follows its own dirty mark. A pane that gets one burst of output and then nothing (a "needs you" or "done" agent) was slow to draw its first screen on the captain's display, so the engine forces a draw 60 ms after a full frame and 250 ms after the last bytes (`SwiftTermEngine.scheduleNudge`, `ConnTerminalView.nudgeDisplay`). In the one environment it could be measured (no display link ticks at all), the first draw lands 55 to 67 ms after the first frame; whether that matches the delay on a real screen is for the captain to confirm.

## Build and run

Command Line Tools and SwiftPM only. No Xcode.

```
./build.sh                 # build/Conn.app (release), about 5 minutes the first time (SwiftTerm dominates); signed with "Conn Local Signing" when present, else ad hoc, see below
./run.sh                   # live: observe-only client of Herdr session "esim"
./run.sh --fixture         # stand-in Herdr with invented agents and pages: safe to screen-share, compose box enabled
./run.sh --fixture --renderer grid   # the same with the cell-grid pane view
./run.sh --session NAME    # another session
./run.sh --write NAME      # let the compose box send to that session (default: none)
./run.sh --text-panes      # poll pane text instead of streaming (works across Herdr protocol changes)
./test.sh                  # unit tests (Swift Testing from the Command Line Tools); CONN_HOSTILE_SCALE=full adds the 2 MB and 12 MB hostile streams;
                           # CONN_HERDR_LAB_SESSION=fm-lab-NAME and CONN_HERDR_LAB_NAV_SESSION=fm-lab-NAME add the Herdr client checks against lab sessions (see "Herdr client mode"; the lab check also covers a launch with the default view: it attaches to the lab session and Stop ends it)
./run.sh --fixture --ui-check   # scripted in-process UI checks (background mode); add no --fixture to run them read-only against session esim
./run.sh --fixture --agent-view --ui-check   # the same launched with the Agent view flag on (run both: they differ in which menu checks can run)
./run.sh --fixture --campus-blocked-network --campus-check   # the same, with the stand-in answering nginx's 403 Forbidden page on every path (what Campus does off the company private network) from the first request
./run.sh --fixture --campus-check            # only the Campus steps of --ui-check, against the stand-in Campus (see "Campus in Conn")
CONN_CAMPUS_CHECK_STOP=stale ./run.sh --fixture --campus-check   # the same, ending after the stale-connection steps (about a minute)
./run.sh --fixture --focus-check             # only the Conn Focus steps of --ui-check (see "Focus sessions and eye breaks"): a hand-moved clock, stand-ins for the sound, `shortcuts`, the Focus and the panel
CONN_EMBED_URL=file:///path/to/embed.html ./run.sh --fixture --campus-check   # the same, plus the steps that draw Campus on a copy of the reader's embed page (without it they print SKIP)
```

**The build installs by rename and signs the bundle.** `build.sh` puts every file into `build/Conn.app` (and `build/FakeHerdr`, `build/FakeCampus`) as a new file plus a rename, never by writing over the old one: macOS caches a code signature per inode, so overwriting a built executable in place makes the next launch die at dyld with "Code Signature Invalid". The last step signs the whole bundle and runs `codesign --verify --verbose=2 build/Conn.app`; the build fails if that does not pass. Check it yourself with `codesign --verify --verbose=2 build/Conn.app`.

**Signing: one stable identity keeps macOS privacy grants across rebuilds.** An ad hoc signature (`codesign --sign -`) has no identity, so macOS treats every rebuild as a new app and forgets what you allowed it (Music, iCloud Drive, other apps' data, App Management, notifications). `build.sh` therefore signs with the code-signing certificate named `Conn Local Signing` when it is in your keychain (set `CONN_SIGN_IDENTITY` to use another name), prints `signed with identity: ...`, and falls back to ad hoc signing, saying so, when there is no such certificate. To create it once: Keychain Access > Certificate Assistant > Create a Certificate, Name `Conn Local Signing`, Identity Type Self Signed Root, Certificate Type Code Signing, then Create. The certificate lists as `CSSMERR_TP_NOT_TRUSTED` in `security find-identity -p codesigning`; that is expected for a self-signed root and signing works. The build never changes the keychain or any trust setting. The first launch after the switch asks for each permission once more, because the identity differs from the ad hoc one; after that the grants stay.

**Which Conn is which: only the primary checkout builds `dev.local.conn`.** macOS opens an app by its bundle identifier (System Settings' "Quit & Reopen" after a privacy switch, `open -b`, Launch Services), and every registered copy with that identifier is a candidate. On 10 Nov the Mac knew eight copies of `dev.local.conn` (the real one, five worker worktrees, two scratch builds) and "Quit & Reopen" opened the oldest worktree copy twice (08:26 and 08:30) instead of the real Conn. So `build.sh` now names the app by where it is built: the primary checkout of the repository (not a git worktree, not under a temporary folder; for Nathan's machine `~/workspace/helm`) builds **Conn** with `dev.local.conn`; every other build is **Conn (dev)** with `dev.local.conn.dev`, which no reopen of the real one can pick and which shows as "Conn (dev)" in the menu bar and the Dock. `CONN_BUNDLE_ID` and `CONN_BUNDLE_NAME` override both. The build also writes a `CFBundleVersion` (the commit count), so two copies that do share an identifier resolve to the newer. Scripted launches keep using their own settings suite (`dev.local.conn.test`), so the new identifier changes nothing for them. Copies registered before this change keep the old identifier until they are rebuilt or dropped: `tools/lsregister-clean.sh` lists every registered Conn copy and, with `--apply`, drops all but the real one (`CONN_KEEP`, default `~/workspace/helm/build/Conn.app`) from the Launch Services registry. It changes only that registry, never a file.

Conn's first launch migrates app-owned data from Helm when the new locations are absent. It moves `~/Library/Application Support/Helm` to `~/Library/Application Support/Conn` and copies the old `dev.local.helm` UserDefaults domain to `dev.local.conn`, renaming Conn-owned `helm.*` keys to `conn.*`. Existing Conn locations are never overwritten. The migration is covered by unit tests.

More options are listed at the top of `run.sh`. Keys: Cmd+K quick switcher (opens the session in the Herdr client view), Cmd+1..9 agents (the sidebar order: agents that need you first, then working, done, idle; see "Open asks on the agent rows"), Cmd+J next agent waiting on you, Cmd+Y swap the live pane for its history and back (Esc also goes back), Cmd+= / Cmd+- / Cmd+0 pane text bigger / smaller / back to the fit, Cmd+O / Shift+Cmd+O / Cmd+S, and in the Editor view Cmd+B (Explorer), Shift+Cmd+E (focus it), Cmd+P (go to file), Opt+Cmd+C and Opt+Shift+Cmd+C (copy path, relative path), Shift+Cmd+] and Shift+Cmd+[ (tabs) (see "The Explorer"), Opt+Cmd+1/2/3 Herdr client / Agent / Editor, Shift+Cmd+W Watch several sessions (see "Watch view"), Ctrl+Cmd+S hide or show the sidebar (see "The sidebar"). The Agent view, Cmd+Y, Cmd+\ and the pane-text keys exist only when the Agent view flag is on (see "The Agent view flag").

**Scrolling a pane.** A live pane cannot scroll: Herdr re-renders the pane for an observer (a full frame clears the screen and writes every row at an absolute position, later frames rewrite changed rows; a real working pane sampled read-only held 0 line feeds in 19,908 bytes), and a terminal only keeps scrollback when line feeds scroll it. Herdr's ANSI form of `pane.read` for the `recent` source is only the screen too, so styled history cannot be seeded either. Instead the clock button in the pane header, Cmd+Y, or a deliberate upward wheel or trackpad scroll over the pane swaps the live pane for a scrollable snapshot of its history (`pane.read` recent, plain text, newest at the bottom, find bar, Refresh, Copy). The stream keeps running and drawing underneath, so "Back to live" shows a current screen at once. Real, styled, live scrollback needs Herdr to expose it (a history call that keeps colour, or scroll-aware frames) or control mode.

**Pane text size.** The font is the largest (7 to 28 pt) at which Herdr's whole cols x rows grid fits the pane's width and height, refitted on every window or split resize; the grid is centred in the slack. Cmd+= / Cmd+- change a zoom factor (0.6 to 2.0 of the fit) that is remembered across launches; zoomed past the fit the left and top edges crop. A pane that is 59 rows tall is height-bound: rows, not columns, set the size, so a wide window does not make its text larger. A different grid (more columns, fewer rows for the width you have) needs the Herdr pane resized, which is a write and belongs to control mode.

**Organizer and reader.** The Organizer pane opens on its Context view every time it is switched to or its page loads (Conn clicks the page's own Context button; the page is not edited). A link in one pane to the other pane's server (localhost, 127.0.0.1 or ::1, the same port), by click or by `target=_blank` / `window.open`, switches to that pane and loads that exact address, hash kept; any other outside link opens in the browser. The two tabs share one container that holds only the selected pane's web view, so a tab always shows its own page; `--ui-check` asks which page a click in the middle of the column would reach after each switch, built from either tab first (with `--fixture`, `CONN_UI_CHECK_SHOT_DIR=DIR` also writes a picture of each step).

**Pinning the reader.** An agent selection and a starred chip both call one pin. When the Reader web view already shows the reader page (same server and path; a `?conn=<n>` query left by an earlier load does not matter) and the page says it follows an address change while open, the pin only changes the address fragment (`location.hash`), so the reader switches in place: no page load, no 19 MB download, no new load time on the row. Conn tells a reader that follows from one that does not by a small script it adds to the reader page before the page's own scripts run; it only notes whether the page listens for `hashchange` and edits nothing. Anything else is a page load as before: the first load, another page or server, a page still loading, a reader that reads `#s=` only at load (it gets `?conn=<n>#s=...`, so WebKit treats it as a new document), or an in-place change that raises an error. The chip and agent highlighting follow the address the reader writes back, in place or after a load. `--ui-check` proves both paths on throwaway pages served from a scratch local port (a window marker survives an in-place pin and is lost on a load), and with the real reader (no `--fixture`) pins it once, read-only. Measured on the live reader in Chrome, 18 switches between 6 starred sessions: 211 ms median (119 to 595) in place against 1,369 ms median (1,088 to 2,052) for a page load.

**The reader follows the row you click, or says it has nothing.** An agent selection (a sidebar click, Cmd+1..9, Cmd+J, Cmd+K, the menu-bar list, and the sidebar following a move made inside the Herdr client) pins the reader to that agent's conversation: the session Herdr names for the pane, else the one its open ask names (`ReaderTarget`, ConnCore). Herdr names a session only after an integration has reported one (its `agent_session` field is omitted until then), so a worker started a moment ago has none; a real pane list shows such Claude panes. For an agent with no conversation the Reader column is covered by "No transcript yet for this agent" and nothing is pinned, instead of keeping the conversation of the agent chosen before, which read as that agent's transcript. When Herdr (or an open ask) later names a session, the notice goes and the reader opens it without another click. With the Herdr client driving (a person's own launch) a sidebar click used to move the client and the highlight but never the reader; it now pins it too, and goes back with the highlight when the client does not confirm the move. One case is the reader's, not Conn's: a session Herdr names that the reader does not list yet (its reading list is its own). The reader then stays on the conversation open (in place) or opens another one (on a load), with its own small notice (`prototype/template.html` in the reader: `followAddress`, "is not on the reader any more, so this stays on the conversation open"; `chooseOpening`, "...so this is another conversation"). Conn cannot tell that from a `/clear` chain, where the reader rightly rewrites the address to a later session, so it does not guess. `--ui-check` (`ReaderFollowCheck`, fixture only) clicks six rows and compares the address, adds a pane with no session to the stand-in Herdr (`fake.add_pane`), checks the notice and that nothing is pinned, reports the session late (`fake.set_session`), and clicks a row with the stand-in client attached; `CONN_UI_CHECK_ONLY=reader-follow ./run.sh --fixture --ui-check` runs just that.

**The sidebar.** The left panel (spaces and agents) hides and shows with Layout > Hide Sidebar / Show Sidebar, Ctrl+Cmd+S (the system's own key for a sidebar, as in Finder and Mail; Cmd+B is the Editor's Explorer and no other menu item uses it), the toolbar button at the top left, and a button at the left of the Watch bar. The choice is remembered across launches (`conn.sidebar.visible` in the app's preferences). Hidden, the panel gives its 251 pt to the centre pane and to the Watch columns (3 columns on a 1500 pt window go from 415 to 499 pt each); with it hidden Cmd+K, Cmd+1..9 and Cmd+J still choose agents, and the Watch bar says so. The control existed from the first slice but forgot its state at every launch and had no button in Watch. `--ui-check` (`SidebarCheck`) reads the menu item's key, checks no other item uses it, runs it twice (from the key event when the inert window matches it, else the item's action), reads the saved value and measures the Watch columns with the panel shown and hidden. The menu item's title following the state (Hide / Show) is seen when the menu opens, a hand check.

**Starred sessions row.** The Reader pane's header row (no "Reader" label: the tab above says it) holds one chip per session starred in the reader's own picker, then the load time and the reload button. A click opens that session in the reader (the same pin an agent selection uses, see "Pinning the reader"; the session already on screen is left alone); the chip for the session on screen is filled. Drag a chip onto another to move it there; the order is kept across launches (the only thing Conn stores about stars). More chips than fit scroll sideways, the selected one is brought into view; with nothing starred the row says where to star. Stars are the reader's: Conn reads `~/.config/pmos-transcript-reader/stars.json` (`CONN_READER_STARS` or the reader's own `PMOS_READER_STARS` names another) and never writes it, looking at the file every 2 s, so a star added or removed in the reader reaches the row without a relaunch. A chip is named by the agent running that session now, else by the reader's own record of the pane (`~/workspace/pmos/setup/transcript-reader/out/pane-labels.json`, `CONN_READER_LABELS` names another), else by the first eight characters of the id. `--fixture` reads invented stars and keeps its order apart from the real one; `--ui-check` reads the row from a drawing of the window, clicks a chip with an event delivered inside the process, and checks a live change of the star list on a scratch copy. A drag needs a real pointer, so the reorder call is checked and the feel is a hand check (ROADMAP N1).

**Watch view.** The toolbar button (columns icon), Layout > Watch Several Sessions or Shift+Cmd+W shows 2, 3 or 4 conversations side by side, in place of the centre pane and the reader column. The count is chosen in the Watch bar or Layout > Watch Columns and is remembered (default 3; each count also remembers its own last setup, see "Watch setups" below). Each column is its own web view on the reader's lite page, `out/live/index.html#s=<session>` (`CONN_LITE_URL` names another address; never the full reader page, never a frame): one whole conversation, about 40 MB for an ordinary one and 220 to 400 MB for the few largest, its own scroll, and its own composer, so Send works in each column with the reader server's own checks (Conn adds none and sends nothing itself). While Watch is on the full reader web view is unloaded; leaving Watch lets go of the columns and loads the reader again, pinned to the selected agent. Choosing another view (Herdr client, Agent, Editor) also leaves Watch. A column's header shows the agent's name and Herdr's state for it, and a close button.

**Watch setups: back where you left it, a setup per count, presets.** A setup is the number of columns and which session sits in which column, left to right (a free column is nothing); `WatchSetup` and `WatchSetups` (ConnCore) hold the rules. (1) Leaving Watch for another view (Editor, Agent, Herdr client) lets the web views go but keeps the setup, and Watch turned on again shows the same count with the same session in the same column, in the same order; each column reopens at its newest turn (or its open ask, as the column rule does). A column you closed stays free: only a setup with no conversation at all, or a column whose session is gone, is filled from the sidebar's order. (2) The last setup is remembered per column count: choosing 2, 3 or 4 columns (the Watch bar or Layout > Watch Columns) opens that count's last setup, and a count never used fills as before (more columns add free ones filled from the sidebar's order, fewer keep the most recently used sessions). Going 3, 2, 3 therefore brings the same three back. A launch opens on the setup it was left in. Restored columns count as used from left to right, so the leftmost is the one a new session replaces first. (3) Presets: Layout > Save Column Setup as Preset... (a sheet asks for the name; the same name, in any capitals, replaces that preset), Layout > Load Preset (turns Watch on and sets the count and every column), Layout > Rename or Delete Presets..., and the same three in the bookmark button of the Watch bar. At most 30 presets, names up to 40 characters. No new shortcut. What Conn keeps (`conn.watch.setups` in its own settings, JSON) is session ids and their order, plus a preset's name: no title, no text. A Campus conversation in a column is its `campus:<id>` key. A remembered session that no longer exists leaves its column free for the normal fill rule, with a notice ("A remembered conversation is gone, so its column is free"). Conn can tell that only for an id the lite page could not open and for a Campus conversation the live Campus feed no longer lists (a signed-out Campus judges nothing gone); a reader conversation the reader no longer lists still gets the reader's own fallback, as any column does. `--ui-check` (`WatchSetupsCheck`, fixture only; also inside the full run): `CONN_UI_CHECK_ONLY=watch-setups ./run.sh --fixture --ui-check` runs the one-launch steps, and two launches in a row prove the relaunch, `CONN_UI_CHECK_ONLY=watch-setups-write CONN_UI_CHECK_HANDOFF=FILE ./run.sh --fixture --ui-check` then the same with `watch-setups-read`. The Layout menu's enabled state and the presets listed under Load Preset are drawn when SwiftUI rebuilds the menu as it opens, which this inert window never does: a hand check. **Every way to the Editor view and back** keeps the setup. Ways in: a click on a file link or on the Documents view's file button in a column, `conn <path>` (Finder's Open With, a drop, Cmd+O after its panel), the toolbar's View picker, File > New Document, Layout > Editor and the other Layout items that show the Editor first. Ways back: the toolbar's Watch button, Shift+Cmd+W, Layout > Watch Several Sessions, and a click on an agent in the sidebar while away followed by any of those (the click changes the selected agent only, never a column). Choosing a view always ends Watch, including the view the window is already on: Watch turned on over the Editor view and then a file opened shows the Editor and the file, where it used to open the file behind the columns and leave Watch on (and a sidebar click then replaced a column). While Watch is on over the Editor view the toolbar's View picker still highlights Editor and clicking that segment does nothing (the Herdr client segment, or the Watch button, leaves Watch): a hand check for a better look. `CONN_UI_CHECK_ONLY=watch-trips ./run.sh --fixture --ui-check` (`WatchTripsCheck`, fixture only, also inside the full run) makes every way in meet every way back with the Agent view off, each way in twice in a row, and the Agent view on; `watch-trips-write` then `watch-trips-read` (with `CONN_UI_CHECK_HANDOFF=FILE` and `CONN_UI_CHECK_QUIT=editor` or `watch`) are the relaunch, quitting in the Editor view or with Watch on.
- *Which column a session goes to.* Every way of choosing an agent while Watch is on (a sidebar row, Cmd+1..9, Cmd+J, Cmd+K, the menu-bar list) follows one rule (`WatchLayout`, ConnCore): a session that already has a column keeps it and nothing else moves, with an open ask the column's address becomes `#s=<session>&m=<asking turn id>` (the lite page scrolls to that reply and outlines it, in place, no page load) and the column flashes an outline once; otherwise the session takes a free column; otherwise it replaces the least recently used column in that column's own place (the same web view, loaded again on the new session so the old conversation leaves memory) and the other columns are untouched. A session opened without an ask opens at its newest turn. "Used" is a click, a scroll, a key or focus inside the column (the page reports it) and showing a session in it. A space click only highlights the space. An agent that Herdr names no session for says so in a notice. When Watch turns on the free columns fill with the selected agent and then the sidebar's order (needs you first); more columns fill the same way.
- *Session links.* A reply in the reader that names another session is drawn as a link, `<a class="session-ref" data-session="<reader session id>" href="...">` (on the lite page its href is the lite page's own `#s=<session id>`; the reader's own code draws it, Conn does not). In a Watch column a click on such a link does not move that column: Conn takes the click before the page sees it (a script it writes into the lite page before the page's own scripts run, one handler on the window in the capture phase, so none of the page's handlers runs for that click and nothing in the page is edited), and opens the session by the same rule as every other way of choosing one: a session that already has a column keeps it (and the column flashes), else a free column, else the least recently used column **other than the one clicked** (the click counts as using the clicked column, and the link never removes the page it sits in). With an open ask the session opens on the asking reply as usual. A link that also names one reply (`data-message="<turn id>"`, which the reader's Tasks board puts on its reply links; a value that is not 6 to 64 letters, digits, `_` or `-` is dropped and the session opens at its newest turn) lands the column on that exact reply: a column that already has the session scrolls to it in place and outlines it, a free or replaced column opens on it, and the reply wins over an open ask. **Cmd-click** on the link instead leaves Watch and shows the normal reader pinned to that session, and to that reply when the link names one (the full reader loads again and is not pulled back to the selected agent's conversation until another agent is chosen; the columns' sessions are kept for the next Watch). Enter on a focused link acts as a click, a middle click as a plain click; other modifiers are ignored. In the full reader view (Watch off) the same link is the reader's own: Conn adds no script there, so it opens that session in normal reading mode as the reader decides. Only a session id of 1 to 64 letters, digits and `-` is accepted; anything else a page posts is dropped.
- *The asking turn.* `WatchModel.openAskTurnID` is the one place that says which turn an open ask is on, and the app wires it to the agent rows' open asks (`AppModel.wireWatchAsks`): a session with an ask under 24 hours opens (or, already open, scrolls in place) on the asking reply, and a folded older ask counts as none, so that session opens at its newest turn. A row with an ask opens the conversation its ask names (the reader's own id for the pane, which can be a later session of a `/clear` chain than the one Herdr names, or the only one when Herdr names none). While Watch is on the full Reader page is unloaded, so the asks are read through a column's lite page (see "Open asks on the agent rows"). A live `--ui-check` turns Watch on, reads the asks through the lite pages with the full page unloaded, clicks the top ask row and reads the outlined reply in its column.
- *Narrow windows.* A column is at least 300 pt wide; when the columns do not fit (4 columns in a small window) they scroll sideways.
- *Launch and checks.* `--watch [2|3|4]` opens on Watch (a scripted launch: it never attaches the Herdr client). `--fixture` columns show an invented lite page (`Resources/fixture/fixture-lite.html`) that follows `#s=` and `&m=` the way the real one does. `--ui-check` turns Watch on through the menu item, checks the full reader is unloaded and every column is its own loaded web view, the counts 2, 4 and 3, and the rule (free column, already open and scrolled to the ask with a flash and the others unmoved, replacement of the least recently used column with the same view and the others unmoved, clicks and keys reported by the pages setting the order), then the session links (the fixture's lite page draws two: a click dispatched in the page is taken and the clicked column does not navigate, an open session keeps its column, a free column is used first, otherwise the least recently used column other than the clicked one is replaced even when the clicked one is the oldest, a Cmd-click leaves Watch for the reader pinned to the session and stays there, and the fixture's full reader page follows the same link itself with no Conn script in it), then leaving Watch. A synthetic Shift+Cmd+letter event is not matched by AppKit's key-equivalent search in the inert test window, so the check reads the menu item's key and modifiers and runs its action; the key press itself is a hand check. Against the real reader (no `--fixture`) it opens the lite page read-only and checks `&m=` against an ask in the glance feed, then looks through the feed's conversations (three columns at a time) for a reply with a real `a.session-ref` link and runs the same route on it: the click is taken and its column does not navigate, the named session shows in another column, a Cmd-click leaves Watch for the full reader pinned to it (the reader writes the address as the first eight characters of the id, so that is what is compared), and in the full reader the link is the page's own. A check that needs a live pane stream (agent mode, compare, history, returning to the app) waits for the stream to be live, up to 12 s, instead of a fixed pause, so a busy machine does not fail it.
- *Hiding a column (Watch focus).* With several sessions on, the ones you are not reading pull the eye. The eye button in a column's header blurs that column's content (the header, with the name and the agent's state, stays readable) and the same button shows it again. A hidden page takes no click, key or focus; it keeps running behind the blur, so it is current the moment it is shown, and a page that loads while hidden is not drawn until its blur is on. The blur is a style Conn gives the page's root element (the reader's and the embed page's own code is not edited), and for a Campus column the embed page is blurred the same way while Conn's own header, banner, question buttons and message box in that column are left out. While a hidden session works nothing shows. When its turn ends and it stays stopped for 3 seconds (a pause between two tool calls is not an ending), the column gets a cue that stays until you show it: a strip under the header, green "Finished while hidden" or orange "Needs you" (the turn ended on a question or a permission prompt), with the time and a Show button, and the column's outline flashes once, with no sound. The state is the one Conn already shows (Herdr's, with a permission prompt Herdr did not call blocked counted as needing you; for a Campus column, the conversation's own while Campus is live); a column with no agent, or Campus signed out, raises no cue. Showing a column that holds a cue lands it on the reply that turn ended with: Conn reads the id of the newest reply from the page (the last `.reply[data-turn]`, the attribute the reader puts on every reply card since its "A reply card names its turn"; a reader without it is read by `data-msg="<turn id>:reply"`) and sets `#s=<session>&m=<turn id>`, so the reader's own landing runs (the reply just under the header, outlined once, a clipped reply opened), while the page is still blurred, and the blur lifts about a third of a second later so the page never visibly jumps; a Campus column's embed page scrolls to its last `.reply` card and its native view to its last reply. Showing a column with no cue moves nothing. Hidden columns are kept by session id with any waiting cue (`WatchAttention`, ConnCore; Conn's settings key `conn.watch.hidden`, ids and cue only, no text), so a Conn quit and relaunch, or leaving Watch for another view, brings the same columns back hidden with their cues; a session that leaves its column (closed, or replaced by another) is no longer hidden, and a session that moves to another column with a change of count stays hidden. No shortcut: which column would it hide? (ROADMAP call W3.) **Opening a folder from the terminal.** `conn .` opens the current folder in the Editor view, as `code .` does for VS Code. `conn` alone is the same; `conn some/folder file.md` opens the first folder in the Explorer and each file in a tab (later folders are ignored with a note). The command is a small shell script inside the app (`Conn.app/Contents/Resources/bin/conn`, source `Resources/bin/conn`). It makes every argument one absolute, physical path (`cd -P`; a missing path stops everything with `conn: no such file or directory: ...` and launches nothing) and runs `open -a <the Conn.app that owns the script> <paths>`, so Launch Services starts Conn if it is not running, or hands the paths to the running one and brings it forward. It never runs Conn's own binary with the paths (AppKit would take them for files and SwiftUI would not open its window), it does not wait for anything to close (so it is not `$EDITOR`), and it has no line numbers or new-window option. File > Install 'conn' Command in PATH links it from `~/.local/bin/conn` (no sudo, no installer; the dialog says when `~/.local/bin` looks off the PATH and shows the line for `~/.zshrc`, and Conn never edits shell files); Reinstall replaces a link to a Conn that moved, Uninstall removes only that link, and a file or a link to anything else is never touched. `CONN_APP` names another app bundle and `CONN_OPEN_FLAGS` adds flags to `open` (tests use `-g -j` so a launch never takes focus). In Conn the call lands in `AppDelegate.application(_:open:)` and `EditorModel.openFromOutside`, the one door for the command, Finder's Open With, the Dock icon, a drop on the window and Open: `OpenRequest` (ConnCore) sorts the paths into the first folder and the files. `build.sh` declares `public.folder` as a document type with `LSHandlerRank None`, so Conn receives a folder but never offers itself as the default app for folders. On a cold start the command's folder wins over the remembered one and the remembered files stay behind the file it named, in either order of the request and the session restore. Unsaved tabs are never touched, so running `conn .` twice loses nothing. `ConnScriptTests` run the real script against a stub `open` (no Conn starts); `--ui-check` calls the same door in process.

Inside it, Copy on a code box copies the code, a web link opens in the browser, and a file link (`.file-ref[data-path]`) goes through the same file check as the reader's (`ReaderFileRef`) into the Editor view. **Campus in Conn.** ShopBack Campus (campus.shopback.com, a hosted opencode workspace) conversations appear in Conn: a CAMPUS section in the sidebar, a live view in the centre, a reader-style transcript in the Reader column, and Campus columns in Watch. Decisions C1 to C9 (the clickable prototype, all answered `a`) are what this section builds.
- *Signing in (C8, the cookie way).* The person signs in to Campus inside Conn: the Campus menu (Sign in to Campus), the "Sign in" line in the CAMPUS section, or the status bar. The sheet is Conn's own web view on `/campus/login` (Google sign-in). Every Campus call then runs same-origin from a hidden, signed-in web view (`CampusWebAuth`): the HttpOnly `campus_session` cookie stays in WebKit's cookie store and Conn's code only ever receives a status, JSON text and event text. Conn never reads, prints, logs, stores or copies a cookie or a token. `CampusAuth` (ConnCore) is the one seam: an API key replaces the cookie by one more conformance, with no change to a view. A scripted launch uses a non-persistent store, so a check never touches a person's own sign-in. The signed-in cookie lasts about an hour (scout report); Conn renews it silently when Google and Campus let it ("The silent session refresh", below), and when it ends the section says so.
- *When Campus is part of a launch.* A person's own launch reads the real Campus. A scripted launch (`--ui-check`, `--shot`, ...) never reaches it unless `--campus` or an address is given; `--campus-url ADDRESS` (or `CONN_CAMPUS_URL`) names another one, `--no-campus` leaves the section out. `./run.sh --fixture` starts a stand-in Campus (`build/FakeCampus`, invented conversations and a login page that sets a cookie) and points the section at it.
- *The CAMPUS section (C1 to C4).* Its own block under SPACES and AGENTS: header "N asks · M working", then My space, then one folded "Team spaces" line that still shows its asks and working count. Rows wear Conn's four marks (needs you, working, done = finished and not yet looked at, idle), sorted asks first (newest ask first), then working, done, idle. A conversation that waits on a question shows the question under its row like a Herdr ask (the same block, "Question" or "Answer sheet" tag). Campus asks are counted with Herdr's in the AGENTS header and are reached by Cmd+J (Herdr agents that wait first, then Campus questions) and Cmd+K (Campus rows after Herdr's, labelled "Campus"); they carry no Cmd+1..9 number. Privacy mode hides Campus text. "done" is Conn's own mark: choosing a row clears it in Conn and leaves Campus's unread alone.
- *The feed (`CampusStore`, ConnCore).* One in-memory feed behind every view; nothing is written to disk. The list (`GET /api/spaces`, then each space's conversations) is read every 30 s (60 s while the stream is up); one event stream (`GET /api/events`, read by `fetch` inside the web view) has reconnect with backoff, a cut after 45 s without a byte, and a backfill (the last 50 messages of every conversation on screen) after a gap. A frame that may change a run's state makes one debounced `GET .../status`, and that answer (`busy`, `needs_you`, `idle`) is what sets the row's mark, so an event name Conn does not know never leaves a row wrong. Event and message payloads are read tolerantly (a missing or renamed field is "unknown", never a crash).
- *The live view and the transcript.* The centre shows steps with tokens, tool calls with their argument, time and result, folded reasoning, streamed text and the question as a card. The Reader column (and a Watch column, C5) shows the transcript the reader's way: your messages, replies with a "N tool steps" line, "Waiting on you" cards, a live strip ("Campus is working: reading table-a.csv") while a run goes, Needs you, Copy and Open in web. Neither is a reader session: the reader's own pages are untouched.
- *Campus transcripts on the reader's own page (E9=a).* The Reader and Watch columns draw a Campus conversation with the pmos reader's embed page (`http://localhost:8768/setup/transcript-reader/out/live/embed.html`, or the file `CONN_EMBED_URL` names), so markdown, tables, code boxes and the "N steps" rows look exactly like a Claude or Codex session. One web view per column; Conn feeds it the conversation as JSON through `window.readerEmbed.set` (`CampusEmbed.json`, ConnCore: the same fields as `CampusTimeline.blocks()`, markdown sent as markdown, the working line only while a run goes) on every change, and the page redraws only the block that changed. The page asks nothing of the reader's server and keeps nothing (its own content policy). Conn does not let the page run on the reader's address: it reads the page itself (200 only, 8 MB at most, refused unless it carries its strict `<meta>` content policy and the entry point), hands it to the web view as text with no base address (an opaque origin, so script in a rendered reply cannot reach the reader's server or its token) and blocks every network load in that view with a content rule list. A link in it goes to Conn: a Campus conversation opens by the usual rule (a plain click by the Watch column rule, Cmd-click in the normal view), any other web address in the browser, and the page never navigates. The header (title, state, Copy, Open in web) and the composer stay native. **The page's own message bar (the reader's composer contract):** when the page has one (`readerEmbed.composer`), Conn turns it on for the conversation in a Reader or Watch column, named after the conversation, and Conn's own text box in that column steps aside (one box, not two; the held-message banner, the writes switch and the pickers stay). The bar gives select-text-to-ask (Comment on this, Reply, Ask about this), comments and the batch, and the page's own 5-second Undo window and Now. When a message leaves the page's window the page posts `send`; Conn types it into the conversation at once through the same gate as every Campus write (the switch, one write at a time, the queue above) with no second 3-second wait, since the page already held it, and answers `readerEmbed.sent` with ok or the reason (the page then gives the text back to its own box). While a run works a page send goes as Steer, as Send does. The page is untrusted (a rendered reply is Campus's text), so the send is held to rules the page cannot meet by itself: it must come from the page's main frame, Conn must have seen a real key or click in that web view within the last 20 seconds (script cannot make one), it can write only to the conversation on screen in its own column (a message that names another is refused), at most 10 go in a minute, and a malformed message (no id, empty, over 8,000 characters) and a send while writes are off are refused with a reason and nothing is sent. With writes off, a signed-out, blocked or unreachable Campus the page is told Send is off and why ("Campus writes are off. Turn them on in the status bar."). Privacy mode takes the bar away with the page. With an older page that has no composer, Conn's own box stays. An open question is left off the page, because the page draws questions but cannot answer one: the "Waiting on you" card with its buttons sits under the page and answers through the usual write gate; an answered or cancelled question goes in and the page draws it quiet. Privacy mode empties the page and shows the redacted native view. The native transcript stays whenever the page is not there: while it loads, when the reader is not running, when the reader is older than the page (404, or a page without `readerEmbed`), after 8 s without an answer, or when it refuses the JSON; a box that gave up tries again when you move to another conversation. A `--fixture` launch asks nothing of the real reader, so it keeps the native view unless `CONN_EMBED_URL` names a file (the `--campus-check` embed steps need one: a copy of the reader's `embed.html`, never the reader on 8768; without it they print SKIP).
- *Watch and links (C5, C6).* A Campus conversation takes a Watch column by the same rule as a reader session (`WatchLayout`: its column if it has one, else a free one, else the least recently used, never the column a link was clicked in; the layout keeps it as `campus:<id>`, which no reader id can be). A Campus column has no Herdr conversation web view (when the embed page is there it has its own, above). A link to a Campus conversation in a Herdr column (`https://<campus>/spaces/<kind>/<folder>/conversations/<id>`) is taken before it leaves Conn and opened by that rule; Cmd-click leaves Watch and shows it in the normal view. The same links in Campus text work the same way.
- *Edge states (C9).* Never signed in: one "Not signed in" line. Starting (`503 opencode_starting`): "starting..." in the header, a skeleton and a note, asked again every 5 s. Login expired (401, or a redirect to the login page; a 403 is never a sign-out, see the next point): the last rows stay, dimmed and marked "as of HH:mm", asks are no longer counted, a note and the live view's banner offer Sign in; the stream stops and the list is asked again every 5 s, so the section comes back by itself after a sign-in. A 403 whose body is `{"error":"module_required",...}` is signed in with a module missing, shown by name in the note; another JSON 403 of Campus's own keeps its text. Offline: "offline" in the header and the status bar; the "Campus is not reachable" note carries a Sign in to Campus button too, because the only other places are the menu bar and the status bar.
- *Campus needs the company private network (Zscaler).* Campus answers only on the company private network (Zscaler private access). Off it, `campus.shopback.com` resolves to a public address whose nginx answers every path with a plain "403 Forbidden" page. Conn calls any 403 whose body is not Campus's own JSON **blocked**, not signed out, on every path (list, timeline, stream, writes, agent bridge, silent refresh). The header and status bar say "blocked", the last rows stay, and the sidebar note says it is the network, not your sign-in, to check that Zscaler (private access) is connected, with **Try again** (never Sign in). The sign-in sheet shows the same message with Try again instead of the raw nginx page (a main-frame 403 or failed load on Campus's host). Each sign-in hop is logged (time, host, path, status; never a query, cookie or token) in Application Support, Conn, campus, `sign-in-hops.log`, and Settings > Campus connection shows when the network last blocked Campus. **Try again drops a connection that outlived the refusal.** WebKit keeps one connection pool per website data store and reuses a pooled connection for every page and every `fetch` of every web view on it. A connection that was open while the network refused keeps answering the refusal after Zscaler is turned on, and Conn's polling and event stream keep it busy, so the 403 stayed until Conn was quit and reopened (Nathan, 2026-11-09: Zscaler on, Try again still blocked, only a relaunch helped). Reloading, a new web view and clearing the caches all reuse that connection (measured); only a different data store dials a new one. So **Try again** (in the sidebar note and in the sign-in sheet) swaps Campus's data store for a new one that carries the session over (the cookies move as opaque objects: Conn reads only a cookie's domain, never a value, to decide which ones belong to Campus's sign-in, and the person stays signed in), rebuilds Campus's web views on it and asks again; and while the network keeps refusing, Conn does the same by itself 20 seconds after the refusal began and every 20 seconds after, so a network that came back is met without a click. It never swaps the store under an open sign-in sheet, and a signed-out or unreachable Campus is never swapped. A person's launch keeps Campus in WebKit's own storage: the first launch uses WebKit's default store as before, the first swap moves Campus to a store with an identifier that Conn remembers in its settings (only Campus's and Google's cookies move out of the default store, and only Campus's own host's cookies are taken out of it; Google's stay because other pages use the default store), and each later swap replaces that store and removes the old one from disk (a removal that fails is retried at the next launch). - *The agent bridge (S2).* Leaders ask Campus through Conn: `fm-ask campus --wait N -- <text>`. **Off at every launch**; the switch is in the status bar ("Agent bridge: off / on · N today"), Campus > Agent Bridge and Settings, and turning it on asks first. A run still going when the wait ends is `working`, not a failure: the reply is final for that request id, so the caller reads on with `campus: read <thread>`. **Which threads:** only the ones the bridge started and the ones the person shared with Share with Agents (a Campus row's menu: read only, or read and send; a thread the bridge started is always shared). The label comes from the `fm-ask` record, a claim any same-user process can forge: the audit records it as claimed. **One request at a time per thread** (a second `continue` on a thread that is busy is refused, so two requests cannot both pass the turn cap on the same count). **Caps:** 8 KB in, 64 KB out; 6 new threads an hour per home, 20 a day in total, 3 working at once, 10 turns a thread; counted from the audit, so a restart does not reset them, and a burst cannot pass the check together. **Refused before anything is sent:** secret shapes (private key headers, bearer tokens, well-known token prefixes, JWTs, `NAME=value` lines that set a secret, long hex or base64 runs) and attachments (an `attach:` header or a data URI). **A permission request is never answered:** it comes back as `needs-answer` with `reason: permission`, and the stand-in has no route a bridge could use to answer one. **Signed out** is answered at once (`signed-out`), never queued; an unexpected answer to a start is `failed: shape`. **Audit:** one append-only JSON line per request in Conn's folder (`~/Library/Application Support/Conn/campus-bridge/audit.jsonl`, 0600): time, sender as claimed, request id, thread, action, byte count, sha256 of the text, outcome; never the text. Campus > Agent Bridge Activity shows the latest requests. **Not a security boundary:** every program you run can already read Conn's web-view cookie store or drive a signed-in browser profile; the bridge narrows the easy path, makes each use visible and capped, and gives you one switch. After every stage Conn reads Herdr's focus pointer (`focused_workspace_id`, `focused_tab_id`; Herdr moves it whenever any client selects something, even the place it already was) and expects the stage's target within 2.5 s. If it does not read the target (the client was in a dialog or copy mode, or its keys differ), the remaining keys are not typed, the highlight goes back and a notice says the client did not switch; nothing is retried on its own. The check is exact when the pointer was somewhere else beforehand; if another screen was already at the target it can only say the pointer is right. A click types keys into the client as the person would, so a click while the client sits in a rename dialog or copy mode types into that. Clicks while the client is not attached only select the item and show the Herdr client view (with its Attach button or its failed-attach notice); with the Agent view flag on they open the Agent view as before. Opening a session from Cmd+K, Cmd+1..9, Cmd+J or Cmd+[ and Cmd+] while the client runs moves the client the same way a sidebar click does.
- *Sidebar follows the client.* Herdr does not report where each attached client is, only the one session-wide pointer above (the place last selected by any client). So the sidebar follows a change only when the person has just typed or clicked in the embedded client (within 2 s), and once when the client attaches (a new client opens where the pointer is). A switch made on another screen while they are not using this client does not move Conn's highlight; a switch made on another screen at the very moment they type here would.
- *A custom client config.* `--client-config PATH` (or `CONN_HERDR_CLIENT_CONFIG`) uses your own file instead and ignores the checkbox. It is checked on every attach (`HerdrClientConfig.validate`): an absolute path, no control characters, a regular UTF-8 file of at most 64 KB, inside Conn's Application Support folder or a temporary folder after symlinks are resolved, and never inside `~/.config/herdr`. A path that fails the check stops the attach and the pane says why.
- *What is shared.* Keys and mouse typed into the client steer only that client: its workspace, tab and pane focus change and no other attached client moves. Herdr's socket API focus commands (`workspace focus`, `tab focus`, `pane focus`, from a script or another tool) are session-wide and move every attached client, this one too. Conn's native panes and sidebar never call them (the sidebar moves the client by typing keys, see "Sidebar control"). The client is also one more attached client, so it takes part in Herdr's pane sizing; the native panes are unchanged and stay observe-only.
- *Started from a Herdr pane.* If Conn itself was launched from inside a Herdr pane, it inherits that pane's `HERDR_ENV`, `HERDR_PANE_ID`, `HERDR_TAB_ID`, `HERDR_WORKSPACE_ID` and `HERDR_SOCKET_PATH`, and Herdr then refuses to run a client ("nested herdr is disabled by default"). Conn removes those five from the client's environment so it is a top-level client of the session it attaches to (found by the lab check).
- *Not part of this slice.* Control mode, native live scrollback, Herdr's bottom tab row and the `mobile_width_threshold` setting. In the lab Herdr switched to its mobile layout below 64 columns whatever that threshold was, so a narrow client pane draws Herdr's phone layout.
- *How it is checked.* Unit tests cover the config path rules, the merge into your config and the launch environment (`Tests/ConnCoreTests/HerdrClientConfigTests.swift`, `Tests/ConnTerminalTests/HerdrClientModeTests.swift`), and the sidebar control: reading the key map from a config, the plan from a sidebar item to key bytes (1 to 9, past 9, tabs, another prefix, order by number, unknown targets) the runner that types a plan and checks the focus pointer, and when the sidebar follows the client (`Tests/ConnCoreTests/HerdrClientNavigationTests.swift`). The pty tests run the real controller against a stub `herdr` script: the client starts with the generated config, typed keys reach it, the keys the sidebar types reach it byte for byte without counting as the person's own typing, it exits, Stop ends it. `HerdrClientLabTests` is the end-to-end check against a real Herdr session: it attaches one client with the sidebar hidden and one with it showing, switches workspace by keys typed into the first client, and checks the second did not move, then stops them. It never runs unless `CONN_HERDR_LAB_SESSION=fm-lab-...` names a throwaway session holding two workspaces, "Lab Alpha" and "Lab Beta", with a pane each that prints `ALPHA tick N` / `BETA tick N`, and it refuses any other name: `CONN_HERDR_LAB_SESSION=fm-lab-NAME ./test.sh --filter HerdrClientLabTests`. `HerdrClientSidebarLabTests` is the end-to-end check of the sidebar control: two attached clients (one hidden-sidebar client with a non-default prefix, one normal), then a sidebar-driven switch of workspace (2, the last, 1) and of tab (2, the last, 1 of the busiest workspace) must move the first client and leave the second where it was, and a key map with the wrong prefix must be reported as not landed. It never runs unless `CONN_HERDR_LAB_NAV_SESSION=fm-lab-...` names a throwaway session holding at least 11 workspaces labelled `NAV01`, `NAV02`, ..., one of them with at least 11 tabs, every pane printing `<label>-T<tab number> tick N`: `CONN_HERDR_LAB_NAV_SESSION=fm-lab-NAME ./test.sh --filter HerdrClientSidebarLabTests`. Both lab checks run headless; no window is opened. Still for a person at a real display: a click on a space and on an agent in the sidebar moves the client in the window and the highlight follows (the app itself was not launched), a switch made inside the client moves the highlight, the notice after a failed switch, and the hidden-sidebar client's look in the window (tab row, borders, colours), mouse and trackpad in the pane, and the Attach, Stop and checkbox controls.

## Focus sessions and eye breaks

A built-in focus timer and the 20-20-20 eye rule (the scout report and its sketch are in the leader-workspaceos home; decisions F1 to F22 are in the ROADMAP's "Decided and deferred"). One focus block of a length you pick each time, no pomodoro breaks inside it. While it runs, every other app's macOS banner is silenced; you see the time left in Conn's toolbar and in the menu bar. Separately, an eye break every 20 minutes. It is **the Mac only** (F18): nothing is shared with your other devices.

**Where it is.** A pill is the first item of the toolbar's right-hand group (`MainView`'s `ToolbarItemGroup(placement: .primaryAction)`): a timer icon when nothing runs, the countdown (`24:13`, purple) while a session runs, a pause icon and the frozen time while paused, `Done` (green) at the end, and a red triangle when Conn Focus did not switch on. Measured with `--focus-check`: the widest pill (`3:00:00`) is 85 points wide and, in a 1,000-point window (the minimum, `App.swift`), pushes no toolbar item into the overflow menu. A click opens the popover: the length (15, 25, 45, 60, 90 or Custom in 5-minute steps up to 180), the eye switch, Start; while running Pause or Resume, +5 min and Stop early (asks first); at the end "Session done" with Restart and "Choose another length". While a session runs, is paused or is done, a **second menu-bar item** shows the same countdown and opens the same controls with Conn behind other apps (it goes when you restart or dismiss Done; it never exists in a test launch). The **Focus** menu has the same actions (no keyboard shortcut: the free Command chords are gone).

**How the other apps go quiet (F1, F12, F17).** macOS has no public call that turns a Focus on, so Conn runs a Shortcut you make once: `shortcuts run "Conn Focus On"` at Start, `"Conn Focus Off"` at the end (the system's Set Focus action, one per shortcut). **Focus > Set Up Conn Focus** (or "Set up Conn Focus" in the popover) is the step-by-step guide, with Check Focus Setup (it only lists your shortcuts with `shortcuts list` and runs none), Allow Focus Status and "Run a 1-minute test". The Focus you make allows **no people and no apps**: Conn's Dock badge and menu-bar count are not notifications, and Herdr's toasts are drawn inside Conn, so neither needs an exception. The agent notifier from the personal repo posts as **AgentNotify** (`com.claude.agent-notify`), so this Focus silences it too (F12); never add AgentNotify to the Focus's allowed apps. The firstmate away-mode "escalations WEDGED" banner is silenced the same way (F17, accepted). Nothing is held back or replayed afterwards (F2).

**When the Focus changes.** Start runs On. Pause keeps it on (F15). The moment the timer reaches zero the chime plays, the state is Done and Off runs (F16); Stop early runs Off; quitting Conn ends the session, removes the marker file and runs Off, waiting up to 4 seconds for it; and the next launch runs Off again if the last run left the Focus possibly on (Conn writes `conn.focus.mayBeOn` before every On and clears it after an Off that worked, so a crash or a kill is covered). The Set Focus action has no timer of its own, so Conn is the only thing that turns it off. Every shortcut call has a time-out (10 seconds, 4 at quit) and the child is ended if it does not stop. Only the two names above are ever run. A failing or timed-out On is a **red warning** in the pill and the popover ("Conn Focus did not switch on. Other apps' banners are not silenced", with Try again and the setup guide); the session goes on without the Focus. A failing Off is a red "Conn Focus may still be on" with Try again.

**Did it really turn on (F21).** After On, Conn asks macOS's public Focus Status (`INFocusStatusCenter`) for up to 3 seconds. Allow Conn once (the first Start shows macOS's prompt; the Info.plist key `NSFocusStatusUsageDescription` is written by `build.sh`; later System Settings > Focus > Focus Status). The answer is only "a Focus is on", never which one: a state of "on" is confirmed, "no Focus is on" after 3 seconds is the red warning, and if you did not allow it, or another Focus was already on before Conn Focus, the state is a neutral "not confirmed" note, never an alarm. A build without that Info.plist key (not from `build.sh`) never calls the check.

**The marker file for other tools (F14).** While a session is running or paused Conn keeps this file, written atomically, and nothing else of Conn's focus feature is visible to other tools:

```
~/Library/Application Support/Conn/focus-session.json
{"pid": 4242, "started_at": 1793000000, "ends_at": 1793001500}
```

`pid` is the Conn process that owns the session; `started_at` and `ends_at` are Unix seconds. While paused `ends_at` is `null` (the session is still on, with no deadline). The file is written at Start, rewritten on pause, resume and +5 min, and removed at Done, Stop early and quit; a launch removes a file whose owner is gone (the pid is not a live process, or it started after `started_at`, so the pid was reused). A reader should treat the file as "a session is on" only if `pid` is alive. The agent notifier skips its spoken "Approval needed" and "Task finished" while such a file exists (that change is in the personal repo, a separate task). Test and scripted launches write to a folder of their own under the temporary folder, never to this path.

**Eye breaks (F8 to F11, F19, F20, F22).** The 20-20-20 clock has its own switch (popover, Focus menu), is remembered, and runs with or without a session. Every 20 minutes a small dark panel floats at the top centre of the display that has the mouse pointer, over every app, every Space and full-screen apps: "Look 20 feet away", a 20-second countdown, **Skip** (counts as skipped, a new 20 minutes) and **Snooze 2 min** (comes back in two minutes, counts as neither), a chime at the start (Submarine, a calm sonar ping) and a different one at the end (Hero, a short rising two-note), both chosen to be easy to tell from Glass and from the sounds Herdr, Claude and the agent notifier already make (the end then shows "Good. Back to it." for two seconds). The panel never becomes the key or main window (`NSPanel`, non-activating, `canBecomeKey` false), so it cannot take the keyboard. While Privacy mode is on it is hidden from screen capture and sharing (`sharingType = .none`) but still shows for you (F22). The session end plays Glass (F19). Tink, the first pick for the breaks, was too short and quiet to recognize, so Nathan asked for a better one (2026-11-09). No break starts while you are away, and coming back restarts the 20 minutes (F10): away is a locked screen, a sleeping display or Mac, or 2 minutes without input.

**How idle and lock are read.** Idle time comes from `CGEventSource.secondsSinceLastEventType` (the same value as `ioreg`'s `HIDIdleTime`; no permission prompt was seen when the probe ran from a terminal). The lock comes from the login session's `CGSSessionScreenIsLocked` flag and the distributed notifications `com.apple.screenIsLocked` and `screenIsUnlocked`; sleep and wake come from `NSWorkspace`'s public notifications. The two lock names and the session key are not documented by Apple: if they ever stop working, the 2-minute idle rule still covers a lock, and a lock that opens and closes between two looks is caught by the latch in `SystemPresence`. The eye clock looks every 5 seconds while idle and every second while a break shows or the popover is open; with the eye clock off and no session nothing ticks. While it ticks, Conn holds an App Nap activity (`TimerTicker`, which still lets the Mac sleep), so a covered Conn does not get its timer coalesced into a late chime; after a sleep the end of a session or a break is noticed on wake.

**The daily total (F13).** "Today: 1 h 25 min focused, 3 eye breaks, 1 skipped" in the popover, with a three-line card behind "Daily total". Three numbers for today under one preference key (`conn.focus.total`), reset when the local date changes; no history, no times of day. The run in progress counts while it runs; a pause does not.

**Where the code is.** `ConnCore/Focus`: `FocusSession` and `EyeBreakClock` (pure value types: every call takes the moment it happens, so tests move a `ManualFocusClock` and never wait; a countdown is a deadline `Date`, so sleep and App Nap cannot drift it), `FocusCoordinator` (drives both, and does what their events call for through small protocols: `FocusSwitching` with `ShortcutRunner`, `FocusStatusReading`, `FocusChiming`, `EyePanelPresenting`, `PresenceReading`, `FocusTicking`), `FocusMarker`, `FocusTotals`, `EyePanelPlacement` and the stand-ins (`FocusStandIns`). `Sources/Conn/FocusPlatform.swift` has the real ones (idle and lock, the two sounds, Focus Status, the timer, the panel) and `FocusRuntime.make`; `FocusViews.swift` the pill, the popover, the menu-bar label, the eye panel's content and the setup guide; `FocusCheck.swift` the `--ui-check` steps.

**Test mode.** A scripted launch (`--ui-check`, `--focus-check`, `--fixture`, `--background`, `--shot` and the rest) runs the feature on stand-ins: no sound, no `shortcuts run` (a recording switch answers instead), no Focus change, a panel that is built but never ordered onto a screen, the test preferences, and a marker folder of its own. A check also gets a hand-moved clock and a ticker that fires only when the check says so. `--foreground --focus-show-panel` lets a person see the panel in a scripted launch (still silent, still on stand-ins); `CONN_FOCUS_EYE_INTERVAL=SECONDS` (at least 5, scripted launches only) shortens the 20 minutes for that look. `--focus-check` asserts the toolbar pill in each state (drawn and read as pixels), the session through start, pause, +5 min, the end, Restart and Stop early, the marker file at every step, On and Off, the red warning and Try again, the eye break and the panel's properties and place, Privacy mode, the away rule, the Focus menu, the toolbar room at 1,000 points and the daily total; `CONN_UI_CHECK_SHOT_DIR=DIR` also writes pictures. The unit tests (`Focus*Tests`, `EyeBreakClockTests`, `ShortcutRunnerTests`) cover both state machines, the marker file, the totals, the placement, and the shortcut runner against a stub script that stands in for `shortcuts`.

**Not verified on a real screen, and how to check (a person does this once).** (1) Make the Focus and the two shortcuts (the guide), press Check Focus Setup, run the 1-minute test: banners from another app stay silent for the minute and return after it; whether macOS asks to allow Conn to run a shortcut, and whether it offers the Focus Status prompt for an ad-hoc signed build, are unknown until then. (2) The scheduled "Reduce Interruptions" Focus on this Mac around a Conn Focus session: what macOS does when Conn Focus ends while a scheduled Focus is active is unknown. (3) The eye panel above a full-screen app, on a second display and with Stage Manager (`./run.sh --fixture --foreground --focus-show-panel` with `CONN_FOCUS_EYE_INTERVAL=10`, then switch the eye clock on): buttons react to a first click and the panel never takes the keyboard (type in another app while it shows). (4) Privacy mode with a real screen share: the panel stays out of the capture (ScreenCaptureKit on newer macOS may ignore `sharingType`; if the panel shows in a share, that is a bug to report). (5) The menu-bar item's countdown redraws each second without flicker. (6) `Dock badge` and the menu-bar bell count during a Focus: expected unchanged (set from the app, not from notifications). (7) The agent notifier's spoken lines are still spoken until its own change that reads the marker file lands.

**Not possible by public API.** Turning a Focus on without a Shortcut; telling which Focus is on; a panel over the lock screen or over a window that uses a level above 25 (screen savers, some system overlays); detecting a meeting or a screen share other than Conn's own Privacy mode.

## Rebuild and restart Conn with Archon

The Archon workflow `conn-rebuild` (`.archon/workflows/conn/rebuild/`) rebuilds Conn from `main`, asks whether to quit and restart the running app, and on a yes quits it and relaunches it the same way on the new build. Every node is a bash step, so it needs no AI provider. Run it after Conn changes land on `main`:

```
archon workflow run conn-rebuild --folder    # from the checkout that holds build/Conn.app
```

`--folder` is the route for this checkout: it has no git remote and is not a registered Archon repository, so `--folder` registers the directory as a folder project and runs in place (`--no-worktree` is meant for a registered repository and was not tried). The run builds, then pauses at the gate and prints the run id.

**Answering the gate.** The question reads "Conn built at COMMIT. Quit and restart Conn now?" with a line saying how Conn is running now.

```
archon workflow status                         # the paused run and its id
archon workflow respond <run-id> approve       # quit Conn and relaunch it on the new build
archon workflow respond <run-id> reject        # leave the new build in place, touch nothing
archon workflow wake                           # only if the run stays paused after an answer (the Adjoe workflow on this install needed it; not yet seen for this one)
archon workflow resume <run-id>                # after a failed run: continues from the failed node
```

| Node | What it does |
|---|---|
| `preflight` | Stops unless the checkout is on `main` with no uncommitted change to a tracked file (untracked and ignored files such as `build/` do not count). Prints the head commit. |
| `find-running` | Finds the Conn running from this checkout's `build/Conn.app/Contents/MacOS/Conn` and records how it was started: its `CONN_ARGS` and its arguments. Says "not running" if it is not. It runs before the build so the restart reuses the arguments of the running app (the build replaces the executable by rename, so the running app is not touched until it quits). It stops if more than one Conn runs from this build. |
| `build` | Runs `./build.sh` (release), the way the running copy is built. On failure it prints the last 40 lines of the build log and stops. It also stops if `main` moved during the build, so the commit in the question is the commit that was built. |
| `confirm-restart` | The gate: approve or reject. |
| `decision` | Turns the answer into one word for the nodes after it. |
| `quit` (approve only) | Asks Conn to quit with AppleScript (`tell application "<path>/build/Conn.app" to quit`), then waits up to `quit_timeout_seconds` (default 30) for the process to exit. If Conn is still running it stops and says so. It never sends a signal or force-kills. If Conn is not running it does nothing. |
| `relaunch` (after `quit`) | Starts Conn with `open -n build/Conn.app`, with the same `CONN_ARGS` (`--env`) and arguments (`--args`) that `find-running` recorded, then waits for exactly one Conn process at that path, checks it is still alive two seconds later, and prints its pid. The build finished before the launch and the process runs from that path, so it is the new build. `open` makes the new Conn a child of the system, not of the workflow, so it outlives the run. |

Things to know:

- **Only `CONN_ARGS` is read** from the running Conn's environment (`ps eww`), never any other variable. Its value ends where the next `NAME=value` starts, so a bare `word=value` inside `CONN_ARGS` would cut it short (`--option=value` is fine). If the environment cannot be read, the gate says so and Conn is relaunched with no arguments. A Conn started with no `CONN_ARGS` is relaunched with none.
- **The first quit can raise a macOS prompt** asking whether the program running Archon may control Conn (Automation). Allow it once. The AppleScript only asks the app to quit; it is not synthesised input (see the test notes below), and it runs only after a person approves the gate.
- **A quit that Conn does not finish** (an editor sheet asking about unsaved changes, for example) makes the `quit` node fail after the timeout. Answer the dialog or quit Conn by hand, then run `archon workflow resume <run-id>`: the `quit` step finds Conn gone and the relaunch goes on.
- **A rejected run is complete.** The new build stays in `build/`; the next launch of Conn, by hand or by another run, uses it.

Tests (no app is started, quit or opened; every external command is a stand-in):

```
archon validate workflows conn-rebuild
archon workflow test conn-rebuild                                  # 10 fixtures, run from a scratch copy of the committed HEAD
bash .archon/workflows/conn/rebuild/tests/test-conn-rebuild.sh     # the step script against the stand-ins, plus static checks on the workflow
```

The stand-ins (`ps`, `git`, `osascript`, `open`, `sleep`, `build.sh`) sit in `fixtures/stub-bin/` and are used only when the `stubs_dir` input names that folder; the step script refuses any other folder.

## Test notes (read before launching the app from a script or an agent session)

A test launch must never take the keyboard or the pointer from the person at the computer. The rules:

1. **Background mode.** `--background` (or `CONN_BACKGROUND=1`) makes the process an accessory (no Dock icon, no menu-bar item), never activates it, makes its windows fully transparent and click-through, and has any window that becomes key give it up. Views still lay out and draw, so in-process checks and captures work. Every scripted launch (`--ui-check`, `--shot`, `--tour`, `--selftest`, `--probe-draw`, `--editor-test`, `--send-test`, `--start-fallback`, `--quit-after`) implies it; `--foreground` or `CONN_FOREGROUND=1` opts out. None of them attaches the Herdr client by itself, and they open on the Herdr client view (the Agent view when its flag is on: `--agent-view`) unless `--mode` says otherwise (`--start-fallback` attaches it, to a stand-in Herdr only). `tools/kill9-orphan-check.sh` and `tools/stall-check.sh` pass it. Going through `open`, use `open -g -j`.
2. **No synthesised input.** No CGEvent, AppleScript or System Events clicks or keystrokes, no cliclick, nothing that moves the real pointer. Drive the UI in-process: the `--ui-check` hooks and direct method calls on the model. Capture with `--shot` / `--tour` (in-process rendering), never by bringing a window forward.
3. **Stop what you start.** Kill every test instance when its check ends (the check scripts do).
4. **Needs a real foreground window?** Do not run it from a script. List it for a person to try by hand. Today that is: the pane's mouse-wheel gesture on a real trackpad, keyboard focus in the compose box, Cmd+= / Cmd+- / Cmd+0 and Cmd+Y typed at the real window, and `tools/measure.py` (it opens a real window on purpose, because drawing cost is what it measures).

## Keyboard ownership (design note, `ConnCore/KeyRule.swift`)

Panes take no keys today, but the rule is fixed before they do:

- App shortcuts always carry Command (Shift or Option may join it: Opt+Cmd+1/2/3 switch the centre view, Cmd+Ctrl+S toggles the sidebar). A chord without Command is never the app's.
- Control and Option (Alt) chords without Command always go to the focused pane (Ctrl-C, Ctrl-R, Alt-B, Esc prefixes); no terminal sends Command chords, so the two sets never clash.
- One chord, Cmd+L, moves keyboard focus between the compose box and the pane. It is ignored while an input method is composing (marked text): then the keys belong to the input method.
- Everything else belongs to whatever has focus.

`KeyRule.route` is the matcher (unit-tested over every modifier combination); `--ui-check` audits every menu shortcut against it. The day a pane takes input, its key view asks `KeyRule.route` before it handles an event.

## Known limits

- Panes are drawn at the size Herdr's own screen gave them (an observer cannot resize a pane), so they are narrow in a wide window. Window-sized panes need control mode (decision D3, step 2), which is not built.
- A stream pane has no scrollback of its own (see "Scrolling a pane"): the history view shows the newest 3000 lines of `pane.read` as plain text, a snapshot, not live. The reader has the full conversation.
- The compose box has only been exercised against the stand-in Herdr. Multi-line messages are refused with a message (a newline may submit early on real Herdr). Not yet tried on real Herdr: an agent that is blocked on a question. Herdr's `agent.prompt` rejects a blocked agent, so it may be the better call for non-blocked agents; that needs a lab session.
- Each visible working pane costs the Herdr server several points of CPU, so streams run only for panes on screen, and stop after 30 s in the background.
- A reader that predates the in-place address change (it reads `#s=` only at load) is still loaded again, 19 MB and about 1 to 1.5 s, when it follows a different agent. See "Pinning the reader".

## Safety model

- Panes are observe-only. The app never resizes a pane and has no control-mode path.
- The only Herdr write is the compose box (`pane.send_input`: text, then Enter). It is refused in code unless the session is on the `WritePolicy` allow list (`--write NAME` or `CONN_WRITE_SESSIONS`), it waits a few seconds with an Undo, and the text returns to the box if delivery fails.
- The only Campus writes are the ones behind the "Campus writes" switch (off at every launch, a 3-second Undo, one at a time, the text returns to the box on failure) and, separately, the ones the "Agent bridge" switch lets leaders make (off at every launch, threads it started or the person shared, caps, an audit, no permission answers). Campus data is kept in memory only, and no cookie or token is ever read by Conn's code.
- Everything that talks to Herdr is in `ConnCore/Herdr`. Session names and pane ids are validated before they reach a socket or a command line.
- Stream bytes are untrusted: CSI parameters are clamped, saved cursors are clamped, frame sizes are checked (500 by 300 cells at most), clipboard and title requests from a pane are dropped, and only http and https links open.
- Observer children get one receipt each (`observers/<pid>.json`: pid and start time of the child and of its owner). A launching instance ends a child (SIGTERM, then SIGKILL after about a second) only when its owner is gone, it is still the same process, its parent is launchd and its command line is still ours; another running instance's children are never touched.

## Dependencies and why SwiftTerm is not a SwiftPM dependency

SwiftTerm (upstream `migueldeicaza/SwiftTerm`, v1.99.2, revision in `tools/deps.lock`) is cloned into `.deps/` by `tools/fetch-deps.sh` and compiled as a plain target through the `Sources/SwiftTermVendored/Upstream` symlink. SwiftPM keeps dependency clones as bare repositories, and this Mac's `safe.bareRepository=explicit` git setting refuses to run inside them, so a URL dependency cannot resolve (SwiftTerm's own manifest also declares dependencies it does not use here). Relaxing a git safety setting to build was not done. Upstream is a tools-6.2 package; compiled here under tools 5.9 it builds in the Swift 5 language mode, so its strict concurrency checks are off. The two files upstream generates with a build plugin (`SwiftTermBuildInfo`, an XTGETTCAP reply table) are stubbed in `Sources/SwiftTermVendored/BuildInfoStub.swift`.
