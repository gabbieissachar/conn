# Transcript reader

Reads Firstmate session logs back as a conversation, and lets you answer a reply in its own Herdr pane.
Design and decisions: `DESIGN.md`.

## Run it

```bash
python3 setup/transcript-reader/reader.py add <session id, 8-char prefix, or Herdr pane label>
python3 setup/transcript-reader/reader.py          # rebuild every listed session, start the server, print the links
```

`reader.py` also has `remove`, `list` and `panes` (live Herdr panes to pick from), and `adopt` (what Sync runs to list the live panes the list lacks).
The reader has its own server, in its own process, apart from `setup/serve.sh` and the pages that one serves. `reader.py` starts it when needed, on port **8768** (8765 and 8766 belong to other pages). For another port, set `PMOS_READER_PORT`, which `reader.py` and `serve.sh` both read. `serve.sh --port` changes only that one command: `reader.py` still looks on 8768 and starts its own server there.
`reader.py` checks which copy of the repo answers on the port and says so, with where that other copy runs (`Port 8768 serves another copy of the repo (/path)`).
Start and stop it by hand with `bash setup/transcript-reader/serve.sh [start|stop|restart|status|passcode] [--port <port>] [--tailnet]` (the last two are for the phone, below). `stop` only stops this copy's own reader server, never another copy's or another app's.
After changing `api.js` or `server.js`, restart it: `bash setup/transcript-reader/serve.sh restart`.

Open the printed `http://localhost:8768/setup/transcript-reader/out/prototype.html` link in one of the supported browsers:

- **Chrome** (checked in Chrome 155 at `http://localhost:8768`): the page, the live badge, Send disabled and enabled (empty box, a working, idle or Done agent, an agent at a permission prompt or in an unknown state, a closed pane), a single message and a batch sent to the right pane, the Documents tab and a message about a file, and phone width (390 px) all work.
- **VS Code Integrated Browser**, the browser tab in VS Code's editor area.

Not supported: the **VS Code Simple Browser**. It shows a page inside a frame, and the page refuses to be framed on purpose (`frame-ancestors 'none'`, `X-Frame-Options: DENY`), so that no other page can embed it. Use the Integrated Browser or Chrome instead. Safari and Firefox were not tried.

Opened in a supported browser, the page:

- **Refreshes itself.** When a listed session writes a new turn, the server rebuilds the pages (at most every 3 seconds, only while a page is open) and the page swaps in the new turns where you are reading. When the page's own code changes it reloads, keeping the replies you expanded and your place.
- **Syncs on demand.** The line under the title says when the page last heard from the server ("Synced 09:02:14", changing with every 2-second poll, and "Not syncing since ..." with an "offline" badge once the server stops answering). **Sync** reads Herdr again and rebuilds from the session logs and the fleet records now, then swaps in the whole build: the session list, each session's live or ended state and the newest turns of every listed session, so any session you switch to afterwards is current, while the conversation you are reading keeps its place. Sync also lists every live Herdr pane running Claude whose session is not on the reading list yet (a `/clear` joins and a label reads as for Follow Herdr), and brings all of them up to date in the same click. A session you took off the list (the page's Close, `reader.py close` or `remove`) stays off until you add, reopen or follow it again, and the default Herdr session is never read. It sends nothing to any pane. It only reads; it writes `out/` like any rebuild. A server started before Sync existed says so and the page reads what it can.
- **Pins messages.** **Pin** on a message or a reply keeps it; **Pins · n** in the controls lists this conversation's pins or all of them, and a click goes to the message (opening the wake-up run that hides it, in place: a conversation already on screen is not drawn again). A pin names the message by its turn's id from the session log, so it holds across rebuilds and `/clear`. Pins are kept in `~/.config/pmos-transcript-reader/pins.json` (`PMOS_READER_PINS` moves it), outside the repo, owner-only (folder 0700, file 0600), holding no message text. A page that cannot reach the server (a file copy, a server that predates pins) keeps them in this browser, and moves them into the file once it can. The hosted copy keeps them in the browser, per viewer.
- **Follows Herdr.** With "Follow Herdr" on, the reader shows the session of the pane Herdr has focused. A session not on the reading list is added. While you write in the message bar, the switch waits until you send or leave the box, and the bar says where Herdr is. The session the page opens on wins over the first focus when the address names it (`#s=…`, which the page keeps up to date) or when this tab read it last (a reload, or the answer sheet's "← Reader").
- **Keeps live panes only.** When a listed session's Herdr pane closes, the server rebuilds the page and `reader.py` drops that session from the reading list. A session cleared with `/clear` stays while its pane runs the newer session. A session is dropped when Herdr no longer lists its pane (within one life of a Herdr session the id of a closed pane is never reused; a session deleted and made again under the same name counts as new panes), when its pane now runs a different session that is not a later part of the same conversation, and when its pane runs no agent and has done so for over 15 minutes since that Herdr session's server started. Within those 15 minutes a pane whose agent has not come back yet (Herdr restarts bring panes back before their agents) keeps its session. A dropped session that runs in a pane again within two weeks of its last turn is listed again, unless you removed or closed it yourself. A session never seen in a Herdr pane (added by id or log path) stays, and nothing is dropped while Herdr shows no pane at all or one of its sessions cannot be read. An empty list is no failure: when the last listed pane closes, the page keeps that conversation on screen as a closed pane, and once none is shown it says so, with Closed panes in the picker. Close takes a conversation off the page too, on to the next one, and a reload does not list it again.
- **Keeps the conversation you are reading when its pane closes.** The page does not move to another conversation or aim the message bar at another pane. It stays on the same turn as a closed pane, with a note saying so and Send off, and the box keeps what you typed. "Keep it on the reader" lists it again until you press Close; picking another session instead takes it off the reader, and it stays under "Closed panes". A reload (new page code, a restarted server) or the conversation's address lists it again the same way and returns to the same place, with no message bar until it is back. An address naming a session the reader can no longer open says so above the conversation shown instead.
- **Titles the browser tab.** The tab reads `<picker name> · Reader` (`· Documents` in the document view, `Fleet timeline · Reader` on the timeline, "Transcript reader" with no conversation open), so tabs of several conversations tell apart; it follows a switch, Follow Herdr, Sync and a label change, in the hosted copy too.
- **Shows what each session is doing.** With the server running, each session in the picker shows its agent's state from Herdr and then its Herdr tab or pane label. A session whose pane was seen but no longer runs it (its agent exited and left the pane at a shell, or the pane closed) reads "closed pane" there and in the header, within one poll. Herdr can keep the id of an agent that has exited, so a pane that names no agent but keeps a session id is checked against what runs in its foreground, as a Claude pane is (plus the session's title only when two listed sessions share a label). The states are: Working, Waiting for you (a permission prompt or question), Done, Idle. The states follow Herdr while the page is open. A session with no running pane shows none. Herdr keeps a finished session Done until you visit its pane there, and it has no way to be told you read it elsewhere, so a Done session you have read here up to its newest turn shows Idle (in the picker and the message bar). That is kept in this browser only and leaves Herdr's own sidebar unchanged; a newer turn makes it Done again.
- **Reopens a closed pane to read.** The session picker lists the sessions an agent runs now, each by its Herdr label alone (a session's title is added only to tell apart two running sessions with the same label, never because a closed one has it). Under "Closed panes" it lists first the sessions still on the reading list that no pane runs (kept after the pane closed, reopened by hand, or never seen in a pane), then the sessions of panes closed in the last two weeks (one entry per conversation). Picking one adds it back, with its documents, and keeps it while its pane stays closed. "Close" takes it off again, and it returns to "Closed panes". From the command line: `reader.py reopen <full id>` and `reader.py close <full id>`; `reader.py add` of a closed pane's session does the same as `reopen`, and says so.
- **Chats with the session.** A message bar sits at the bottom of the Conversation and Documents views and writes to the session on screen (Enter sends, Shift+Enter starts a new line; on a phone, the Send button sends). For several comments at once, "Add" (Cmd+Enter or Ctrl+Enter) puts each one into a batch kept for that session in the tab, and Send then sends them all as one numbered message, with what is in the box last. Commenting on a new passage while a pointed comment sits in the box adds that comment to the batch first. Each batched comment has Edit (back into the box, keeping its place, so Send or Add puts it back where it was) and remove; a `/` command cannot join a batch. "Exact text" (one click) shows the whole message a batch sends, numbering and every pointer in full, and while the batch is not empty a one-line note in the bar says so ("3 comments - Exact text shows what Send types"). "Sends exactly" folds a long pointer (a reply the session no longer holds adds a log path) to one line that opens on a tap, so your own words stay in view. On a phone the batch list folds after each Add; tap its heading to open it. A send removes only what it sent: anything written or added while it runs stays. It sends only when Herdr says the agent is idle, working or done, and the pane's foreground process is Claude running that session (not a shell it was suspended to). "Reply" on a reply, or "Comment on this" after selecting a passage in it, attaches a pointer to the bar, shown under "Sends exactly". A sent message shows at once, faded, until the session's log has a message of yours with the same opening words. A plain message takes you to the end of the conversation; a reply to an older turn keeps your place. `/clear`, `/exit`, `/quit`, `/compact`, `/logout` and `/rewind` ask first. The draft keeps its pointer and, during Edit, its place, across a reload or a switch to another session; after a `/clear` in the pane, the draft and batch move to the pane's newest session, and a pointer written before the clear says so. The pointer names the reply instead of copying it, for example `Re your reply at 10:57 ("Checkpoint for group A"): A2=link-only`. When the session no longer holds the reply (the pane cleared it since, or it came before the session's last compaction), the message also names the log and gives what the reply asked, or else its first few hundred characters. The answer sheet's Send does the same with the picked answers.
- **Empties the pane's input box before sending.** Text typed in the Herdr pane and not sent would otherwise join the front of the message, so each send first deletes it (Ctrl+K and Ctrl+U, up to about 100 screen lines). These keys never stop a working agent, unlike Ctrl+C or Esc. Anything you had typed there is gone, so send from the pane itself if you want to keep it.

A `file://` copy of the page still reads, but cannot refresh, follow or send.

In any copy of the page:

- **Opens at the latest turn.** Opening a conversation, from a new tab, the session picker, the Conversation tab or Follow Herdr, scrolls to its newest turn, placed under the header. Wake-ups folded after it stay as one-line rows below. Three or more folded wake-ups in a row share one row that gives their time span; the newest turn stays open while it has no reply yet, and the newest reply always stays open (a worker often reports its finished task in a wake-up's turn), so you see where the session stands. A reload of the same conversation in the same tab keeps your place instead.
- **Documents.** A markdown file a reply or a message names (`requirements.md`, `02-Projects/x/work-log.md`, an absolute, `~` or `file://` path) opens from a button under that reply or message, in the Documents tab: the file rendered beside its contents list (one column with a folding list at phone width). Select a passage and "Comment on this", or use "Message about this file", to send a message naming the file, its section and the passage. A relative name is looked up under the latest `cd` directory the reply gave before it, then among the files the session's own tool calls named in that turn or earlier (latest first, so `design-baseline.md` finds the copy the agent just edited in another folder), then under the turn's working directory and its parents below your home folder. Files over 512 KB are skipped, and so is a file outside your home folder and the temp folders (agents quote paths from material they read). The page shows each file as it was at the last rebuild.
- **HTML files.** An HTML file a reply or message names (a throwaway sketch, a prototype, a report: `sketch.html`, an absolute, `~` or `file://` path) gets a button of its own (`◧`) beside the markdown ones, found by the same name rules and the same limits on where it may be (under your home folder or the temp folders, after links are followed), and opens in the Documents tab **rendered**, not as source. A file over 8 MB is skipped. The page does not embed it: the button asks the server (`html-open`), which checks the file again and gives an address, and the page shows that in an iframe with `sandbox="allow-scripts"` and no `allow-same-origin`, so the file's scripts run but cannot read the reader's origin, cookies, token or API, open windows or move the page. The server answers each request with a Content-Security-Policy that sandboxes the response itself and lets the file load only from beside it (no network, no frames, no forms, no `fetch`), so a sketch that calls a CDN or a web font shows without it. **As of now:** the file is read from disk at each load, not at the last rebuild, so **Reload** shows the agent's latest edit (the button itself, and which files are offered, come from the last rebuild; Sync refreshes them). Pictures, styles, scripts and other pages beside the file and below its folder load (`.png .jpg .gif .webp .avif .svg .ico .bmp .css .js .html`), never a dot file or folder, a link leading out of the folder or another type; fonts, module scripts and media do not load (they need a CORS answer, which this server never gives). A file directly in your home folder or a temp folder gets only the files in that folder. **Desktop width** lays the page out 1280 px wide and shrinks it to fit a phone, **Full screen** fills the screen (Esc or Exit leaves it), **Open alone** opens the file by itself in a new tab, still sandboxed, with the browser's own pinch-zoom, and "Message about this file" writes to the session as for markdown (a passage cannot be selected inside the frame). The hosted and sealed copies do not show HTML files. The address a file is shown from holds a random key that only a page with the reader's token was given, kept in memory for an hour of disuse (so it also works on the phone, where the sandboxed frame cannot send the session cookie), and the HTML button is the one route besides the pages that answers without the token.
- **Firstmate's instructions.** A Firstmate doorbell only points to a steering inbox, so the reader shows the inbox messages it delivered in its place, whether the doorbell names the inbox by path or by name (looked up in the state folder of the session's home, then its parent home's). A doorbell rung again for a message already shown reads as one line, and one whose message cannot be found says so. A worker's task instructions, which arrive as a pointer to one file, show that file from its `# Task` heading. A message sent while the agent was busy takes the rest of that turn, so the message before it reads "Answered below" rather than "No reply".
- **Markdown.** Replies, status lines and documents are drawn as GitHub-flavored markdown by a vendored copy of markdown-it (`prototype/vendor/`, pasted into the page, so nothing loads at run time): bold, italics, ~~strike~~, nested and task lists, quotes and tables. Raw HTML in the text shows as text, and only an http(s) address becomes a link.
- **Code boxes.** Fenced code (commands, snippets) shows in a wrapped box with a Copy button that copies exactly the code. Tables render as tables.
- **Collapsible header.** The chevron at the top right folds the tabs and controls into one line naming the session, document or view; **Follow** stays in that line, the same switch as Follow Herdr in the controls. On a conversation that line is a session picker, so you can switch sessions without opening the controls. Tap the line (elsewhere) or the chevron to bring them back. The choice is kept in this browser.
- **Search.** The magnifier beside the chevron, `/`, or Cmd/Ctrl+F opens a search row under the title. The browser's own find cannot see what the page folds away (wake-ups, working notes, the rest of a clipped reply) or has not drawn (every other conversation), so Cmd/Ctrl+F opens this search instead, and a second Cmd/Ctrl+F inside its box hands over to the browser's. Cmd/Ctrl+Shift+F opens it on all conversations. It matches plain text, case-insensitively, as typed (`fm/some-branch`, `c7639c`, a path, a port): every word must be in the same message, reply or working notes, in any order, a "quoted phrase" stays together, and two characters are the least. **This conversation** tints every match on the page, the current one stronger, and counts messages ("4 of 37"; the tooltip gives the occurrences). **All conversations** searches the reading list and lists the matches (**List** brings the list back), the conversation with the newest match first and the newest match first inside it. **Anyone, You, Replies, Needs you** and **Firstmate** narrow whose words. Enter and Shift+Enter (or Cmd/Ctrl+G) step through the matches, a row in the list picks one, and Esc closes. A match opens only what hides it, in place, through the opener its own button uses: a run of folded wake-ups, a folded wake-up, a clipped message or reply, the working notes. Closing folds back what the search opened and keeps your place. There is no index, no server route and no model: it runs on the turns the page already holds, so a query goes nowhere (the hosted copy, sealed or not, searches in the browser once the turns are open, and its "All conversations" covers the conversations this device has loaded, saying how many of the listed ones that is). While you search, the tabs and controls fold away as in the folded header, and Follow Herdr waits until the search is closed. A rebuild or Sync runs the query again without moving you and keeps the current match, and a reload for new page code keeps the search (query, scope, filter and match) in this tab. Highlights use the browser's CSS Custom Highlight API (Chrome 105, Safari 17.2, Firefox 140); without it the current message flashes instead.
- **Cleared sessions.** `/clear` starts a new session log in the same pane. The reader joins the sessions a pane ran into one conversation, under the newest one, with a divider at each clear: the log it cleared is the one written within two minutes before the `/clear` that names the same remote-control link, in any project folder (a session resumed from another directory keeps its old folder), else the one written then in the same folder. Naming any of them (`#s=…`, `reader.py add`) opens the whole conversation, and `reader.py` adds the newest one to the reading list. Replying to a turn from before a clear goes to the pane's current session, and the message names the earlier log, since that session never saw the turn. Claude started again in the same pane (Firstmate swaps a worker's model that way) joins the same way, when the new session starts within ten minutes of the old log's last write. A log is also written to long after its last turn (a Herdr restart rewrites the link and cost records, which carry no time), so the time of its last dated record counts as well as its modification time, and a `/clear` made hours after the last turn still names the log that holds the same remote-control link. Herdr keeps the first session id it was told after such a restart, so for a Claude pane whose id no running Claude holds, the reader asks Herdr for the pane's foreground process and reads that process's session from Claude Code's own record (`~/.claude/sessions`); a pane back at its shell runs no session.

## Open it from the phone

The reader can also listen on this Mac's Tailscale address, so a phone on the same tailnet opens it directly, with no SSH tunnel. It is off unless you ask for it, and it asks for a passcode.

```bash
bash setup/transcript-reader/serve.sh passcode              # once: type a passcode (8+ characters) twice, nothing is shown
bash setup/transcript-reader/serve.sh restart --tailnet     # or start --tailnet; PMOS_READER_TAILNET=1 is the same switch
bash setup/transcript-reader/serve.sh status                # "Tailnet address served: http://100.x.y.z:8768 (passcode required)"
```

Then open `http://<the Mac's Tailscale address>:8768` on the phone (`tailscale ip -4` prints it), type the passcode and it opens the reader.

- **What listens.** Loopback as before, plus the address `tailscale ip -4` gives, on the same port. Never `0.0.0.0` or another interface (the server refuses any address outside Tailscale's 100.64.0.0/10). If Tailscale is not running, or no passcode is set, it starts loopback only and says why in one line.
- **The passcode.** `serve.sh passcode` reads it from the terminal without echo; it is never an argument, printed or logged, and there is no default. Only a salted scrypt hash is stored, in `out/passcode.json` (owner-only, gitignored with the rest of `out/`; `PMOS_READER_PASSCODE_FILE` names another file). A new passcode signs every phone out at once, and so does removing the file. The Herdr organizer page on port 8765 uses this same passcode and file (below): one passcode, one sign-in for both.
- **What a signed-in phone gets.** A correct passcode sets a session cookie (`pmos_session`: HttpOnly, SameSite=Strict, a random token whose hash names a small owner-only file in `out/passcode.json.sessions/`), so a server restart keeps the phone signed in, and a session ends after 30 days without use. The cookie is on top of the usual checks: every page and API route, Send and pins included, still needs the Host and Origin to be exactly the tailnet address and port, Fetch-Metadata and the page's token. Requests on `localhost` need no sign-in, as before.
- **What works from the phone.** The whole reader, the message bar included, as on the Mac: the live badge, Sync, Follow Herdr, Pins (kept on the Mac), the Documents tab, and every way to send to the session's Herdr pane (a message with the Send button, Reply, "Comment on this", the batch with Add then Send, "Message about this file", the answer sheet's Send, and a `/` command after its confirm). The page counts as served, and so enables all of it, on `localhost` or on a Tailscale address (100.64.0.0/10) with the token the server writes into the page; a file copy or any other address stays read-only. If the Mac's server restarts, the page reloads once to pick up the new page token (a draft in the box is kept), and the phone stays signed in; after a new passcode it reloads to the passcode page and a correct passcode brings the same page back. On a touch screen Send, Add, the links under the box and the Pin and Reply pills are 44 px (Pin and Reply 34 px) tall.
- **Wrong passcodes.** The third wrong one in a row from an address locks it for 30 seconds, and each after that doubles the lock up to 15 minutes.
- **When it will not open.** The passcode page says why in words (a wrong passcode, a lock and its wait, a refused request, no answer within 10 seconds, a cookie the browser did not keep, a script that did not start), and every attempt is one line in `out/server-<port>.log` on the Mac: the time, the phone's address and the outcome, never the passcode.
- **Sign out.** Open `http://<address>:8768/transcript-reader/signout` (the page at `/transcript-reader/signin` shows a Sign out link while you are signed in). It ends the sign-in for the organizer page too.
- **Not covered.** It is plain HTTP: Tailscale encrypts the traffic between the devices, but the browser shows no padlock and the cookie has no `Secure` flag. Anything else on the tailnet can reach the port and see the passcode page, which is why the passcode is required. A browser on the Mac itself may be sent through a corporate proxy that blocks tailnet addresses; use `localhost` there.

## Open the Herdr organizer from the phone

The Herdr workspace organizer page (`apps/wip-herdr-workspace-organizer.html`) is served by the shared app server, `setup/serve.sh`, on port 8765. It can listen on the same Tailscale address as the reader, with the same passcode and the same sign-in: signing in to either app signs the phone in to both, and signing out of one signs out of both. It is off unless you ask for it.

```bash
bash setup/transcript-reader/serve.sh passcode    # once, the same passcode as the reader (skip it if the reader's is set)
bash setup/serve.sh --restart --tailnet           # or start --tailnet; PMOS_SERVE_TAILNET=1 is the same switch
bash setup/serve.sh status                        # "Tailnet address served: http://100.x.y.z:8765/apps/wip-herdr-workspace-organizer.html"
```

Then open `http://<the Mac's Tailscale address>:8765/apps/wip-herdr-workspace-organizer.html` on the phone (`tailscale ip -4` prints the address), type the passcode and the page opens. Restarting `setup/serve.sh` restarts the shared server for every app it serves; they come back on loopback as before.

- **What listens.** Loopback as before, plus the Tailscale address on port 8765, with a request handler of its own that serves only the organizer page, its API (`/api/herdr-organizer/*`), its Refresh snapshot route and the sign-in. Every other path, the other apps and every file of the repo included, answers 404 there, signed in or not. Never `0.0.0.0` or another interface. If Tailscale is not running, or no passcode is set, it starts loopback only and says why in one line.
- **The passcode.** The reader's (`PMOS_READER_PASSCODE_FILE`, else `setup/transcript-reader/out/passcode.json`); `setup/serve.sh` has no passcode command of its own.
- **Every guard stays.** The page's API still needs the Host and Origin to be exactly the tailnet address and port, Fetch-Metadata, JSON bodies, the per-start token and one change at a time, plus the sign-in. Everything the page can do on the Mac it can do from the phone, restarts and switch files included, each behind its own confirm as before.
- **At phone width.** On a touch screen every button, tab, field and checkbox row is at least 44 px tall, and long commands wrap. The page loads its fonts from Google, so the phone needs internet access as well as the tailnet.
- **When it will not open.** The passcode page says why in words, and each sign-in attempt is one line in `/tmp/pmos-serve-8765.log` on the Mac. A browser on the Mac itself may be sent through a corporate proxy that blocks tailnet addresses; use `localhost` there.
- **Sign out.** `http://<address>:8765/herdr-organizer/signout`.

## The hosted copy

The way towards reading the transcripts from a phone while the laptop is off (the hosted reader plan, ships 1 and 2).

**Nothing is hosted.** Everything below runs on this laptop and writes only to `out/`: no cloud account, bucket, domain or upload exists, and no code here talks to one. Hosting it (ship 3) waits for a written ShopBack security or IT exemption for keeping these transcripts on a personal Cloudflare account, or else for the in-policy alternative, an app in ShopBack's Replit workspace (plan sections 5 and 6).

```bash
python3 setup/transcript-reader/sync.py --build-only                 # every fleet session
python3 setup/transcript-reader/sync.py --build-only --reading-list  # the local reader's list, to compare the two pages
```

It writes `out/hosted/`: the shell page `index.html`, `index.json` (the conversation list), one object per conversation, per named document and per week of fleet records, and a manifest. A run builds a conversation again when one of its logs changed, when the reader's own rules changed (a fix to the parser, say), or when a steering inbox or task-instruction file it shows changed; it rewrites an object only when its content changed. `--full` builds everything again. Its help (`--help`) lists the files and the scope. The reader's server serves the shell beside the local page: `http://localhost:8768/setup/transcript-reader/out/hosted/index.html`.

The shell is the same page as the local reader, loading `index.json` and then one conversation, document or week at a time, so it shows the same conversations, turns, replies, steering messages, documents and fleet timeline. It differs only where a copy without the laptop must:

- **No Follow, Reopen or Close; Send goes through a queue.** Nothing here changes the reading list. The message bar, Reply, "Comment on this", "Message about this file" and the batch are the local page's own, but Send does not reach Herdr: it queues the message for the laptop (see "Send" below). The answer sheet (`sheet.html`, opened from "Answer sheet →" and each "Answer these questions →") is the local one: the same cards from a grill-me reply, the same one-line keyed answer (`A1=accept;A2=inline`), with Copy and a Send that queues the same line.
- **Says how old it is.** A line under the title says "As of 14:02", the time the laptop built it, and turns into "Laptop asleep or not syncing since 14:02" once that is over 10 minutes old.
- **Herdr as of the build.** The picker shows each agent's state as Herdr reported it at the build, and drops it once the build is old; the line under the controls keeps it, with its time ("Working at 14:02").
- **Every conversation, by home.** The picker groups the conversations by home, newest first, each starting with the replies that need you since your last message ("2 since your last message") and its last activity. That count is only for a conversation a live Herdr pane runs: one whose pane has closed says "· closed pane" instead, as on the local page. The page opens on the newest conversation with such a reply. The line under the controls keeps the local page's own count of every reply that needs you.
- **Slower refresh.** Every 30 seconds while the page is visible it reads `index.json` again and swaps in a conversation whose stamp changed, where you are reading. New page code reloads it.

### Send, through a queue (local only)

The hosted page cannot reach Herdr, so Send is a request the laptop carries out when it is awake (plan section 8). All of it is local: no network, and every test and lab run uses a fake Herdr.

1. **The page queues it.** Send writes a request, `{id, session_id, text, at}`, through the reader's own server (`POST /api/transcript-reader/queue`, behind the same guard and token as Send) into `q/<uuid>.json` in the copy's folder. A sealed copy's page gzips and seals the request itself, under the key it holds and with its own path bound in, so the server stores `q/<uuid>.json.enc` bytes it cannot read. Nothing is sent to Herdr, and the bar says "Queued for <pane> at 14:05. The laptop sends it when it is awake." The faded message in the conversation reads "Queued … waiting for the laptop to send it".
2. **The sync sends it.** Every `sync.py` run (`--build-only`, which drains `out/hosted/`, or `--dry-run`, which drains that and the bucket) first runs `drain.js` on each folder that has a request waiting. For each one it asks the local reader's own send (`api.js` `sendPrompt`, the same code as the local Send) whether the session is a conversation of this copy, whether one live Herdr pane runs it, whether that pane's agent is Claude running that very session in the foreground (not suspended to a shell) and not at a permission prompt or question; then it empties the pane's input box and sends the text as one message. Nothing starts when no request waits.
3. **A receipt comes back.** `r/<uuid>.json` (sealed: `.json.enc`) says `sent` with the pane's name, or `refused` with the reason in the same words the local Send uses. The page asks for it every 4 seconds while one is waiting, and shows "Sent by the laptop at 14:06 · waiting for <pane>" or "Not sent · <reason>" with Dismiss. A reload keeps the queued messages of that tab.

Rules the drain keeps: a refusal is final (nothing retries by itself; you send again); a request whose own time, sealed inside it, is over 12 hours old is refused as expired, and one dated more than 10 minutes ahead (a wrong clock on the device) is refused; a request is never sent twice (a "sending" receipt is written first, a run that stopped midway turns it into "refused: interrupted", and the ids handled are also kept on the laptop only, in `out/`, for as long as a copy could still be fresh); a sealed bucket takes only requests sealed under its key and a plain copy only plain ones, as the caller says and never as the folder looks; receipts older than a week go; at most 50 requests wait. Wipe takes `q/` and `r/` with the rest.

```bash
python3 setup/transcript-reader/sync.py --build-only      # drains out/hosted/q
HOSTED_READER_PASSPHRASE=... python3 setup/transcript-reader/sync.py --dry-run   # drains it and out/bucket/q
HOSTED_READER_PASSPHRASE=... node setup/transcript-reader/drain.js out/bucket --sealed   # or just the drain
```

`HOSTED_READER_HERDR` names the Herdr binary (default `herdr` on PATH); the printed LaunchAgent carries the folders of `node`, `python3` and `herdr`. To try it without touching a real pane, point that variable at a script that records its arguments (the tests do).

### The sealed copy (a dry run of the sync)

`--dry-run` is the sync agent of ship 2 with its one target, a local folder (`out/bucket/` by default) laid out as the bucket would be. Each run builds as above, then takes the conversations active in the last 90 days, the documents they name and the fleet weeks of the last 90 days, and:

- **Redacts.** Every text in every object goes through `redact.py`: AWS keys, `sk-` API keys, GitHub, GitLab and Slack tokens, JWTs, bearer tokens, private keys (also one cut off before its END line), passwords and secrets in URLs, any secret given a value (`PASSWORD=...`, `db_password = ...`, `"token": "..."`, `old token=... is dead`; a name like `TOKEN_HEADER`, a `$reference` or a placeholder stays), and 64-hex tokens become `[redacted:<kind>]`. It looks for secrets, not personal data. The counts, never the text, go to `out/hosted/redactions.json`. The laptop's own copy keeps the original.
- **Encrypts.** Each object is gzipped and sealed with AES-256-GCM under a key derived from your passphrase (PBKDF2-SHA256, 600,000 rounds; the salt is in `k/params.json`, which holds no secret), its own path bound in, so the host could neither read one nor pass one off as another. The page opens them in the browser.
- **Writes only what changed**, deletes what fell out of the 90 days, and seals the index again at least every 5 minutes, so the "As of" line stays fresh while the laptop is awake.

```bash
export HOSTED_READER_PASSPHRASE='YOUR_PASSPHRASE_HERE'   # or leave it unset to be asked in the terminal
python3 setup/transcript-reader/sync.py --dry-run
python3 setup/transcript-reader/sync.py --wipe                  # empty out/bucket/ of what the dry run wrote
python3 setup/transcript-reader/sync.py --launch-agent          # print a LaunchAgent that runs the dry run every minute
```

The passphrase is read from the environment or the terminal only, and never written or printed. A passphrase the bucket does not know stops the run; `--new-passphrase` seals everything again under it (losing the passphrase loses nothing). The LaunchAgent is only printed, to install yourself if you want it: it reads the passphrase from your login keychain at each run (`security add-generic-password -s pmos-hosted-reader -a "$USER" -w` stores it, asking for it), and it runs while the Mac is awake.

To review it locally, start the reader's server and open the sealed copy beside the local page: `bash setup/transcript-reader/serve.sh start`, then `http://localhost:8768/setup/transcript-reader/out/bucket/index.html`. It asks for the passphrase once; "Remember on this device" (on by default) keeps the derived key, never the passphrase, in this browser until "Forget this device".

## What it touches

- Reads Claude Code session logs and its running-process records, the fleet homes' records, Herdr's session list and snapshots, and the markdown files messages and replies name. It lists the HTML files they name (`out/html-files.json`, paths only, never served) and the server reads one only when you open it.
- Writes `out/`, the passcode hash (`out/passcode.json`, only on `serve.sh passcode`), and the pins file (`~/.config/pmos-transcript-reader/pins.json`, only on a pin or an unpin; it holds which messages are pinned, not their text). `out/` is gitignored: the pages embed private transcripts. Like Claude's own logs, `out/` and everything in it is the owner's alone (folders 0700, files 0600), and each rebuild narrows any file an earlier version left readable by others. That includes `out/parsed/`, each log's turns as last parsed: a rebuild parses again only the logs that changed since (or all of them once the parser changes), and removes a parsed log no build has used for a week. A rebuild started by hand while the server runs its own waits for it to finish.
- Sends a prompt to one Herdr pane, only on a Send click (or, for the hosted copy's Send, when `drain.js` carries out a queued request), and only to the one live pane whose agent runs that listed session. It refuses an agent waiting at a permission prompt. It never starts, stops or closes a Herdr session, tab or pane, and never addresses the default Herdr session.

The server routes are in `api.js`: the pages under `out/` (the hosted shell and its objects in `out/hosted/` and `out/bucket/` too) and `/api/transcript-reader/*` use the Herdr organizer's guard (exact Host and Origin, Fetch-Metadata, a per-start token) and send no CORS header, so another website cannot read the transcripts or send a prompt.
The reader's server serves nothing else, and `setup/serve.sh` refuses any request into the reader's `out/` folder, so no other app shares the pages' origin. Still, no endpoint hands out the token.
The server writes it into a page only when a browser tab opens that page, and the page refuses frames and cuts off whoever opened it.
A restarted server has a new token: an open page reloads itself once to pick it up (not while you are typing).
A path that the file system resolves into `out/` (another letter case, Unicode form or a symlink) is answered by `api.js` on the reader's server, and refused with a 404 by `setup/serve.sh`.
